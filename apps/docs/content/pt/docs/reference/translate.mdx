Depois de ativar o [i18n](/docs/content/i18n), cada edição a uma página de origem desatualiza silenciosamente as suas traduções. O `blume translate` fecha esse ciclo: calcula exatamente que páginas estão em falta ou desatualizadas em cada locale, traduz‑nas em modo headless com um CLI de agente local e regista o que fez num livro de registo versionado, para que a próxima execução — e o CI — saibam o que está atualizado.

```bash
blume translate --claude
```

```
blume translate  3 item(s) · 2 locale(s) · Claude Code

  ✔ docs/guides/install.mdx → fr 24.2s $0.11
  ✔ docs/guides/install.mdx → de 22.8s $0.10
  ✔ meta titles (2) → de 4.1s $0.01

  Translated 3 files into 2 locales · 1 adopted · 14 already up to date · 51.1s · $0.22
```

## Como funciona

O Blume é o dono do pipeline; o agente apenas traduz texto. Para cada ficheiro que precisa de trabalho, o Blume constrói um prompt de tradução, executa o CLI do agente em modo headless com as suas ferramentas de ficheiros, shell e web desativadas, valida a estrutura da resposta e escreve ele próprio o ficheiro de destino — [Claude Code](https://claude.com/claude-code) com `--claude`, ou [Codex](https://developers.openai.com/codex/cli) com `--codex`. O Blume não guarda chaves de API e não chama nenhum modelo por si.

Cada escrita validada é registada em `blume.translations.json` na raiz do projeto: para cada ficheiro de origem e locale, um hash da origem no momento em que foi traduzida. **Faça commit deste ficheiro.** É assim que uma nova execução distingue entre "já traduzido" e "traduzido, mas a origem mudou desde então" — e é o que torna possível o portão de CI.

O livro de registo é gravado após cada ficheiro concluído, por isso interromper uma execução longa (Ctrl+C) perde, no máximo, as traduções que estavam em curso — a execução seguinte retoma de onde parou. Por omissão, os ficheiros são processados 4 de cada vez; aumente esse valor com `--concurrency` se a sua máquina e os limites de taxa do agente o permitirem.

As novas execuções são incrementais: uma origem que não mudou desde a última tradução é ignorada, pelo que executar `blume translate` depois de editar uma página traduz uma página por locale. Quando uma página desatualizada é retraduzida, o agente vê a tradução existente e é instruído a manter o seu registo, dialeto e terminologia — uma edição de um parágrafo na origem produz um diff de tradução de um parágrafo, não uma reescrita de raiz.

## O que é traduzido

- **Páginas** — ficheiros `.md`/`.mdx` no locale predefinido. O agente traduz a prosa e apenas os valores de frontmatter visíveis para humanos (`title`, `description`, `sidebar.label`, `sidebar.badge`, `seo.title`, `seo.description`). Os destinos seguem o seu parser: `fr/guides/install.mdx` com `dir`, `guides/install.fr.mdx` com `dot`.
- **Títulos de navegação de pastas** — com o parser `dir`, os títulos [`meta.ts`](/docs/content/meta) necessários de cada locale são traduzidos numa única chamada em lote, e o `meta.ts` gerado por locale copia todas as outras chaves (`order`, `pages`, `icon`, `collapsed`) tal e qual, para que a barra lateral do locale mantenha a sua ordenação.

As traduções que escreveu à mão são **adotadas, nunca substituídas**: uma tradução que existe mas não tem entrada no livro de registo é marcada como atual e deixada intacta. Só o `--force` a retraduz.

## Validação

A estrutura nunca é confiada ao agente. Antes de escrever, o Blume verifica cada resposta e reconstrói o ficheiro a partir da origem:

- O frontmatter é reconstruído a partir dos dados do ficheiro de origem, com apenas os seis valores traduzíveis sobrepostos — as chaves que o agente inventou são descartadas, as chaves que apagou são restauradas, e `slug`, `icon`, `order` e as datas são, por construção, idênticas às da origem.
- O número de blocos de código tem de corresponder ao da origem, o corpo não pode estar vazio e o frontmatter tem de ser analisável.

Uma resposta que falhe a validação não escreve nada — o item é reportado como falhado e a execução prossegue. Tudo o que teve sucesso permanece registado no livro de registo, pelo que uma nova execução repete apenas as falhas.

## Falhar o CI

O `blume translate --check` é o portão só de leitura: reporta todos os pares em falta e desatualizados e sai com código diferente de zero quando há dessincronização, sem executar um agente nem escrever nada.

```bash
blume translate --check           # exit 1 when translations are missing or stale
blume translate --check --json    # machine-readable drift report on stdout
```

```yaml .github/workflows/translations.yml
- run: npx blume translate --check
```

O relatório JSON tem o mesmo formato `diagnostics` + `summary` que o `blume validate --json`, o `blume audit --json` e o `blume eval --json`, com a dessincronização agrupada por locale. As traduções escritas à mão (não registadas) nunca fazem falhar o portão.

## Limitações

- A tradução de títulos de meta existe apenas no parser `dir` — o parser `dot` não tem mecanismo de `meta.ts` por locale. Um `meta.ts` que exporte por omissão uma função é ignorado com um aviso; escreva à mão a cópia desse locale.
- As origens remotas e provenientes de CMS são ignoradas: não existe um ficheiro local onde escrever a tradução.
- As etiquetas dos separadores do cabeçalho vivem em `blume.config.ts`, não no conteúdo — localize‑as aí com [mapas de etiquetas por locale](/docs/content/navigation#tabs).
- A qualidade da tradução é do agente. Reveja o resultado como qualquer outra contribuição — o livro de registo só garante atualidade, não fluência.

## Flags

- `--claude` / `--codex` — qual o CLI de agente que traduz. É obrigatório exatamente um (exceto com `--check`).
- `--check` — reportar a dessincronização e sair com código diferente de zero, sem escrever nada.
- `--concurrency <n>` — sessões de agente em paralelo. Por omissão, `4`; máximo `16`.
- `--locale <codes>` — locales de destino separados por vírgulas (por omissão, todos os locales não predefinidos).
- `--force` — retraduzir tudo, incluindo ficheiros atualizados e escritos à mão.
- `--timeout <seconds>` — limite de tempo do agente por ficheiro. Por omissão, `600`; o limite existe para apanhar agentes bloqueados, pelo que as páginas grandes têm margem para terminar.
- `--json` — emitir o relatório em JSON no stdout, em ambos os modos.
