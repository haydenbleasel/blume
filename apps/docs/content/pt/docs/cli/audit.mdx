[`blume validate`](/docs/cli/validate) lê o seu _conteúdo_; `blume audit` lê o _site gerado_. Ele rastreia o HTML em `dist/` depois de um build e reporta problemas de SEO e de saúde do site: títulos, meta descriptions, canonicals, cards do Open Graph e do X, headings, hreflang, imagens, o sitemap, `robots.txt` e dados estruturados.

Como foi o Blume que gerou o site, cada achado indica o arquivo-fonte **e a linha do front matter** que o corrige, e não só a URL que um crawler veria:

```
⚠ Meta description too long or too short   5 pages
    /docs/configuration/export    content/docs/configuration/export.mdx:3
    fix: Rewrite `description` in the frontmatter to fit the length range.
```

Rode depois de um build:

```bash
blume build
blume audit
```

Os achados são agrupados por verificação em vez de listados por página, então o relatório funciona como uma lista de tarefas. Use `--verbose` para expandir cada página afetada com todos os detalhes, e `--only`/`--skip` para trabalhar uma categoria de cada vez. `blume audit --list-checks` imprime o catálogo completo, que também é o [catálogo de verificações](#check-catalog) no fim desta página. O `docsUrl` de cada achado aponta para a entrada correspondente lá.

## Flags

- `--fail-on error|warning|info`: o gate de CI. Sai com código diferente de zero a partir dessa severidade. O padrão é `error`; `--strict` é um alias para `--fail-on warning`.
- `--url <origin>`: também sonda um deploy ao vivo para verificar códigos de status, headers de resposta e redirecionamentos configurados.
- `--external`: sonda os links externos pela rede.
- `--ignore <glob>`: junto com `--external`, não sonda um link externo cuja URL corresponda ao glob, como `--ignore "https://api.acme.example/**"`. Repita a flag para adicionar mais padrões. A correspondência funciona do mesmo jeito que em [`blume validate --ignore`](/docs/cli/validate#flags), e os links internos são sempre verificados.
- `--only <check|category>` / `--skip <check|category>`: restringe o relatório a essas verificações ou categorias, ou as exclui dele (separadas por vírgula). Um termo que não corresponde a nenhuma verificação ou categoria gera um erro que sugere a mais próxima, então um erro de digitação não esvazia o relatório sem você perceber.
- `--list-checks`: imprime todas as verificações que a auditoria pode reportar e sai.
- `--verbose`: lista cada página afetada com o detalhe completo de cada achado, em vez de só as primeiras.
- `--json`: emite o relatório como JSON no stdout.
- `--codex` / `--claude`: passa os achados para o Codex ou o Claude Code corrigirem de forma interativa.

## Fazendo o CI falhar [#failing-ci]

O código de saída é o contrato. Por padrão, `blume audit` só falha em erros, ou seja, coisas que com certeza estão quebradas, como um link para uma página que nunca foi gerada, um loop de redirecionamento ou um sitemap inválido. Achados consultivos (uma description curta, um título duplicado) são avisos e não fazem o build falhar:

```bash
blume audit                      # fails on errors
blume audit --fail-on warning    # also fails on warnings
```

## Verificando um deploy ao vivo [#checking-a-live-deployment]

Algumas coisas só o servidor real consegue dizer: se uma página que existe em `dist/` na verdade retorna 404 por causa de um rewrite errado, se as respostas estão comprimidas, se um header `X-Robots-Tag` está desindexando silenciosamente uma página cujo HTML parece perfeitamente normal e se cada URL antiga em [`redirects`](/docs/deployment#redirects) realmente redireciona para onde você configurou. Aponte a auditoria para um deploy para adicionar essas verificações:

```bash
blume audit --url https://docs.example.com
blume audit --url https://docs.example.com --external   # also probe outbound links
```

Essas requisições saem como as de um cliente HTTP comum, e não como as de um crawler: a auditoria não envia o user agent do Googlebot nem o de um crawler de IA, já que a proteção contra bots de um host pode bloquear um cliente que finge ser um deles. Uma regra de firewall ou de CDN que trata crawlers de forma diferente não é testada, então verifique-a com as ferramentas do próprio crawler, como a Inspeção de URL do Google Search Console.

A auditoria faz uma requisição para a URL antiga de cada redirecionamento exato (um padrão não indica uma URL única para requisitar). Se ela retornar 404, é um erro. Se responder 200, é um aviso: um host que não lê o arquivo de redirecionamentos que o build gerou serve ali a página de meta refresh do build em vez de um redirecionamento HTTP, e os leitores seguem essa página, mas os crawlers talvez não. Veja [Redirecionamentos](/docs/deployment#redirects) para saber o que cada host lê.

Os links externos são classificados, em vez de simplesmente reprovados. Um 404 ou 410, ou um nome de host que não resolve, é um link quebrado que você pode corrigir. Já qualquer outro status de erro (um 401 ou 403 de um site que barra bots, um 429, um 5xx), uma conexão recusada ou um tempo esgotado geralmente é rate limiting ou uma instabilidade no site de outra pessoa, e é reportado como aviso. Use `--ignore` para deixar de fora as URLs que a auditoria não consegue verificar de onde ela roda, como um domínio de exemplo ou um servidor local.

## Corrigindo os achados com um agente [#fixing-the-findings-with-an-agent]

Se você usa o [Codex](https://developers.openai.com/codex/cli) ou o [Claude Code](https://claude.com/claude-code), a auditoria pode passar os achados direto para ele:

```bash
blume audit --codex   # or --claude
```

Isso grava o relatório JSON completo em um arquivo, com todas as páginas afetadas e não só a prévia de três páginas do terminal. Depois, abre o agente de forma interativa com um prompt que o guia pelos achados: editar o arquivo-fonte que cada achado indica, aplicar a correção sugerida e rodar `blume build` e `blume audit` de novo até o relatório ficar limpo. A sessão é interativa de propósito: você revisa as edições pelo próprio fluxo de permissões do agente, e o agente é instruído a nunca corrigir um achado apagando conteúdo.

`--only` e `--skip` restringem o que é repassado ao agente da mesma forma que restringem o relatório, então você pode enviar uma categoria de cada vez.

## O que é e o que não é verificado [#what-it-does-and-doesnt-check]

O conjunto de verificações é propositalmente mais enxuto que o de um crawler de SEO de uso geral. Boa parte do que um crawler desses reporta não tem como acontecer em um site Blume. Ele nunca emite `rel=nofollow`, e os bundles do Vite com hash de conteúdo nunca estão faltando nem redirecionam. Reportar isso como zeros permanentes só ensinaria você a ignorar o relatório.

Limites que vale deixar claros:

- **Dados estruturados** são validados quanto à boa formação (JSON válido, um `@context`, um `@type` em cada nó). O Blume não valida contra o vocabulário completo do schema.org nem contra as regras de rich results do Google.
- **Contraste** é verificado para as cores que a configuração do seu tema define, e não elemento por elemento. A auditoria não renderiza as páginas, então uma cor que você escreve à mão no MDX ou no `theme.css` não é medida.
- **Core Web Vitals** não são verificados. Eles precisam de um navegador de verdade, e uma flag que silenciosamente não medisse nada seria pior do que não ter flag nenhuma. Por isso, `blume audit` reporta as causas de layout shift que _consegue_ ver offline (imagens sem `width`/`height`, assets grandes demais) e deixa o resto de lado por enquanto.

Tudo o que a auditoria não executou é reportado como ignorado, em vez de passar silenciosamente:

```
⊘ network      skipped — pass --url <origin> (12 checks)
⊘ external     skipped — pass --external (2 checks)
```

## Catálogo de verificações [#check-catalog]

Todas as verificações que `blume audit` pode reportar, agrupadas por categoria, com a severidade padrão, o nível em que rodam e a correção que o relatório sugere. `--only` e `--skip` aceitam esses ids (sem o prefixo `BLUME_AUDIT_` também funciona) ou a chave de uma categoria. A chave nem sempre é igual ao heading da categoria, então use esta tabela: `blume audit --only i18n`, e não `--only Internationalization`.

| Categoria           | Chave             |
| ------------------- | ----------------- |
| Acessibilidade      | `accessibility`   |
| Conteúdo            | `content`         |
| Duplicados          | `duplicates`      |
| Indexabilidade      | `indexability`    |
| Links               | `links`           |
| Redirecionamentos   | `redirects`       |
| Cards sociais       | `social`          |
| Internacionalização | `i18n`            |
| Assets              | `assets`          |
| Sitemap             | `sitemap`         |
| robots.txt          | `robots`          |
| Descoberta por IA   | `ai`              |
| Dados estruturados  | `structured-data` |
| Deploy ao vivo      | `network`         |

### Conteúdo [#content]

#### Tag title ausente ou vazia [#title-missing]

`BLUME_AUDIT_TITLE_MISSING` · erro · a partir do HTML gerado

Correção: adicione um `title` ao frontmatter da página.

#### Várias tags title [#title-multiple]

`BLUME_AUDIT_TITLE_MULTIPLE` · erro · a partir do HTML gerado

Correção: remova o `<title>` extra do layout ou do MDX da página.

#### Título longo ou curto demais [#title-length]

`BLUME_AUDIT_TITLE_LENGTH` · aviso · a partir do HTML gerado

Correção: reescreva o `title` no frontmatter para que fique dentro da faixa de tamanho.

#### Meta description ausente ou vazia [#description-missing]

`BLUME_AUDIT_DESCRIPTION_MISSING` · aviso · a partir do HTML gerado

Correção: adicione uma `description` ao frontmatter da página.

#### Várias tags meta description [#description-multiple]

`BLUME_AUDIT_DESCRIPTION_MULTIPLE` · erro · a partir do HTML gerado

Correção: remova o `<meta>` de description extra do layout ou do MDX da página.

#### Meta description longa ou curta demais [#description-length]

`BLUME_AUDIT_DESCRIPTION_LENGTH` · aviso · a partir do HTML gerado

Correção: reescreva a `description` no frontmatter para que fique dentro da faixa de tamanho.

#### Tag H1 ausente ou vazia [#h1-missing]

`BLUME_AUDIT_H1_MISSING` · aviso · a partir do HTML gerado

Correção: dê um `title` à página. O Blume o renderiza como o `<h1>` da página.

#### Várias tags H1 [#h1-multiple]

`BLUME_AUDIT_H1_MULTIPLE` · aviso · a partir do HTML gerado

Correção: rebaixe o `# Heading` extra no corpo para `##`. O Blume já renderiza o `title` como h1.

#### Poucas palavras [#low-word-count]

`BLUME_AUDIT_LOW_WORD_COUNT` · info · a partir do HTML gerado

Correção: expanda a página ou incorpore-a a uma página maior.

#### Níveis de heading pulados (ex.: de h2 para h4) [#heading-skip]

`BLUME_AUDIT_HEADING_SKIP` · info · a partir do HTML gerado

Correção: ajuste o heading para o nível imediatamente abaixo. Níveis pulados quebram o aninhamento do sumário e a estrutura lida por leitores de tela.

#### Página com data no futuro [#future-dated-page]

`BLUME_AUDIT_FUTURE_DATED_PAGE` · info · a partir do HTML gerado

Correção: corrija a `date` ou segure a página até o momento em que ela deve ir ao ar.

#### Viewport não definido [#viewport-missing]

`BLUME_AUDIT_VIEWPORT_MISSING` · erro · a partir do HTML gerado

Correção: restaure o `<meta>` de viewport no seu layout ejetado.

### Duplicados [#duplicates]

#### Título duplicado [#duplicate-title]

`BLUME_AUDIT_DUPLICATE_TITLE` · aviso · a partir do HTML gerado

Correção: dê a cada página um `title` diferente. Os mecanismos de busca o mostram como o título do resultado.

#### Meta description duplicada [#duplicate-description]

`BLUME_AUDIT_DUPLICATE_DESCRIPTION` · aviso · a partir do HTML gerado

Correção: dê a cada página uma `description` diferente.

#### Páginas duplicadas sem canonical [#duplicate-content]

`BLUME_AUDIT_DUPLICATE_CONTENT` · aviso · a partir do HTML gerado

Correção: mescle as páginas ou, em todas menos uma, aponte `seo.canonical` para a página que deve ser indexada.

### Indexabilidade [#indexability]

#### deployment.site não está definido [#site-not-set]

`BLUME_AUDIT_SITE_NOT_SET` · aviso · a partir do HTML gerado

Correção: defina `deployment.site` no blume.config.ts com a URL pública do site.

#### deployment.site é inferido no momento do deploy [#site-inferred-at-deploy]

`BLUME_AUDIT_SITE_INFERRED_AT_DEPLOY` · info · a partir do HTML gerado

Correção: audite um build parecido com o de produção (ex.: `VERCEL=1 VERCEL_PROJECT_PRODUCTION_URL=<host> blume build`) ou o próprio deploy com `--url <origin>`. Não fixe `deployment.site` no código, porque a plataforma o define a cada deploy.

#### Página é noindex, mas declara um canonical [#canonical-on-noindex]

`BLUME_AUDIT_CANONICAL_ON_NOINDEX` · aviso · a partir do HTML gerado

Correção: remova o canonical das páginas noindex. O Google trata essa combinação como contraditória e pode ignorar um dos dois.

#### Página de rascunho está no build [#draft-page-published]

`BLUME_AUDIT_DRAFT_PAGE_PUBLISHED` · aviso · a partir do HTML gerado

Correção: gere o build de novo sem `--preview` antes de fazer o deploy, ou remova `draft: true` se a página já estiver pronta para ser publicada.

#### URL canonical ausente [#canonical-missing]

`BLUME_AUDIT_CANONICAL_MISSING` · aviso · a partir do HTML gerado

Correção: defina `deployment.site` para que o Blume possa emitir URLs canonical absolutas.

#### Página não canônica [#canonical-not-self]

`BLUME_AUDIT_CANONICAL_NOT_SELF` · info · a partir do HTML gerado

Correção: aponte `seo.canonical` para esta página, ou remova-o para usar o canonical autorreferente padrão.

#### Canonical aponta para uma página quebrada ou que redireciona [#canonical-bad-target]

`BLUME_AUDIT_CANONICAL_BAD_TARGET` · erro · a partir do HTML gerado

Correção: aponte `seo.canonical` para uma página que existe e não redireciona.

#### Protocolo do canonical não corresponde ao do site [#canonical-protocol-mismatch]

`BLUME_AUDIT_CANONICAL_PROTOCOL_MISMATCH` · erro · a partir do HTML gerado

Correção: use em `seo.canonical` o mesmo protocolo de `deployment.site`.

#### Página não é indexável [#robots-meta-unexpected]

`BLUME_AUDIT_ROBOTS_META_UNEXPECTED` · info · a partir do HTML gerado

Correção: remova `noindex` do frontmatter da página se ela deve ser indexada.

#### Página excede o limite de rastreamento de 2 MB do Googlebot [#html-too-large]

`BLUME_AUDIT_HTML_TOO_LARGE` · erro · a partir do HTML gerado

Correção: divida a página. O Googlebot para de ler um documento HTML em 2 MB.

#### Header X-Robots-Tag conflita com a meta robots da página [#robots-header-conflict]

`BLUME_AUDIT_ROBOTS_HEADER_CONFLICT` · erro · requer `--url`

Correção: remova o header X-Robots-Tag ou alinhe-o com a meta robots da página.

### Links

#### Página tem links para uma página quebrada [#link-to-broken]

`BLUME_AUDIT_LINK_TO_BROKEN` · erro · a partir do HTML gerado

Correção: corrija o destino do link ou crie a página para a qual ele aponta.

Com [`deployment.base`](/docs/deployment#subpath-deploys), um link relativo à raiz sem a base é reportado aqui, já que o host não serve nada deste build nesse caminho. Uma URL completa no mesmo host, mas fora da base, não é reportada: é assim que uma página aponta para outro app que o host serve ao lado da documentação.

#### Página tem links para um redirecionamento [#link-to-redirect]

`BLUME_AUDIT_LINK_TO_REDIRECT` · aviso · a partir do HTML gerado

Correção: aponte o link direto para o destino, sem passar pelo redirecionamento.

#### Página órfã (acessível só pela navegação) [#orphan-page]

`BLUME_AUDIT_ORPHAN_PAGE` · aviso · a partir do HTML gerado

Correção: adicione um link para esta página no corpo de uma página relacionada.

#### Link interno fixa a origem do próprio site [#internal-link-absolute]

`BLUME_AUDIT_INTERNAL_LINK_ABSOLUTE` · aviso · a partir do HTML gerado

Correção: use um caminho relativo à raiz (`/docs/x`) para que o link continue funcionando em previews e com `basePath`.

#### Página tem links internos de saída com nofollow [#internal-link-nofollow]

`BLUME_AUDIT_INTERNAL_LINK_NOFOLLOW` · info · a partir do HTML gerado

Correção: remova `rel="nofollow"`, porque ele impede que esta página transmita autoridade internamente.

#### Barra dupla na URL [#double-slash-url]

`BLUME_AUDIT_DOUBLE_SLASH_URL` · erro · a partir do HTML gerado

Correção: verifique `basePath` / `deployment.base`. Uma barra no final de um deles produz `//`.

#### Fragmento do link não corresponde a nenhum id na página de destino [#anchor-broken]

`BLUME_AUDIT_ANCHOR_BROKEN` · aviso · a partir do HTML gerado

Correção: aponte o fragmento para um heading que existe na página de destino, ou corrija o heading ao qual ele se referia.

#### URL contém maiúsculas, underscores ou espaços [#url-style]

`BLUME_AUDIT_URL_STYLE` · info · a partir do HTML gerado

Correção: renomeie o arquivo-fonte para um slug em minúsculas e com hifens. Se a URL antiga já tiver sido publicada, adicione um redirecionamento a partir dela.

### Redirecionamentos [#redirects]

#### Redirecionamento quebrado [#redirect-broken]

`BLUME_AUDIT_REDIRECT_BROKEN` · erro · a partir do HTML gerado

Correção: aponte o redirecionamento para uma página que existe.

#### Loop de redirecionamento [#redirect-loop]

`BLUME_AUDIT_REDIRECT_LOOP` · erro · a partir do HTML gerado

Correção: quebre o ciclo em `redirects`, porque ele nunca se resolve.

#### Cadeia de redirecionamentos [#redirect-chain]

`BLUME_AUDIT_REDIRECT_CHAIN` · aviso · a partir do HTML gerado

Correção: aponte cada salto direto para o destino final.

#### Redirecionamento por meta refresh [#meta-refresh]

`BLUME_AUDIT_META_REFRESH` · aviso · a partir do HTML gerado

Correção: use um redirecionamento de verdade no `blume.config.ts` em vez de um meta refresh.

#### Origem do redirecionamento também é uma página real [#redirect-source-is-page]

`BLUME_AUDIT_REDIRECT_SOURCE_IS_PAGE` · erro · a partir do HTML gerado

Correção: remova o redirecionamento ou apague a página que ele encobre. Um caminho não pode ser as duas coisas, e o que os leitores recebem depende do host.

#### Redirecionamento de HTTPS para HTTP [#redirect-to-http]

`BLUME_AUDIT_REDIRECT_TO_HTTP` · erro · requer `--url`

Correção: redirecione para a URL HTTPS.

#### Site ao vivo não redireciona como configurado [#redirect-not-served]

`BLUME_AUDIT_REDIRECT_NOT_SERVED` · erro · requer `--url`

Correção: faça o deploy do arquivo de redirecionamentos que o seu host lê (veja Redirecionamentos na documentação de deploy) ou indique o host em `deployment`.

Vira um aviso quando a URL antiga responde 200 (a página de meta refresh) ou redireciona para um lugar diferente do destino configurado.

### Cards sociais [#social-cards]

#### Tags Open Graph ausentes ou incompletas [#og-incomplete]

`BLUME_AUDIT_OG_INCOMPLETE` · aviso · a partir do HTML gerado

Correção: adicione uma `description`. O Blume preenche o resto das tags Open Graph para você.

#### Imagem Open Graph ausente [#og-image-missing]

`BLUME_AUDIT_OG_IMAGE_MISSING` · aviso · a partir do HTML gerado

Correção: defina `deployment.site` para ativar as imagens OG geradas, ou defina `seo.image` na página.

`BLUME_AUDIT_OG_IMAGE_SMALL` · aviso · a partir do HTML gerado

#### URL do Open Graph não corresponde ao canonical [#og-url-mismatch]

`BLUME_AUDIT_OG_URL_MISMATCH` · aviso · a partir do HTML gerado

Correção: alinhe o `og:url` com a URL canonical da página.

#### Card do X (Twitter) ausente ou incompleto [#twitter-card-incomplete]

`BLUME_AUDIT_TWITTER_CARD_INCOMPLETE` · aviso · a partir do HTML gerado

Correção: defina `seo.x.handle` no blume.config.ts para que o X possa atribuir a autoria do card.

`BLUME_AUDIT_HREFLANG_XDEFAULT_MISSING` · info · a partir do HTML gerado

`BLUME_AUDIT_HREFLANG_BAD_TARGET` · erro · a partir do HTML gerado

`BLUME_AUDIT_HREFLANG_CONFLICT` · erro · a partir do HTML gerado

Correção: cada idioma de um grupo hreflang deve indicar exatamente uma página.

### Acessibilidade [#accessibility]

Estas verificações rodam na configuração do seu tema, e não em cada página: uma cor do tema é uma escolha única para o site inteiro. A verificação resolve as cores do mesmo jeito que o build (o tom de um preset para cada modo, e rótulos brancos ou escuros sobre preenchimentos) e mede cada cor de texto que o tema desenha em relação à razão de contraste WCAG AA para texto de corpo, 4,5:1, nos modos claro e escuro.

#### Cores do tema não atingem o contraste WCAG AA [#theme-contrast-low]

`BLUME_AUDIT_THEME_CONTRAST_LOW` · aviso · a partir da configuração do tema

Correção: escolha um tom mais escuro para o modo claro ou um mais claro para o modo escuro, definindo cada modo com `theme.accent: { light, dark }`.

Ela verifica o texto na cor de destaque sobre a página, os rótulos sobre preenchimentos de destaque e de `action`, e o texto de corpo e secundário sobre um `background` personalizado. Cada achado indica o par, o modo e a razão de contraste.

#### Não é possível verificar o contraste de uma cor do tema [#theme-color-unchecked]

`BLUME_AUDIT_THEME_COLOR_UNCHECKED` · info · a partir da configuração do tema

### Sitemap

#### Página indexável fora do sitemap [#indexable-page-not-in-sitemap]

`BLUME_AUDIT_INDEXABLE_PAGE_NOT_IN_SITEMAP` · aviso · a partir do HTML gerado

Correção: remova `draft`/`hidden`/`noindex` do frontmatter da página se ela deve ser indexada. Um `public/sitemap.xml` substitui o sitemap gerado, então adicione a página nele ou apague esse arquivo.

#### Página noindex no sitemap [#noindex-in-sitemap]

`BLUME_AUDIT_NOINDEX_IN_SITEMAP` · erro · a partir do HTML gerado

Correção: uma página noindex não deve ser anunciada no sitemap.

#### Página não canônica no sitemap [#non-canonical-in-sitemap]

`BLUME_AUDIT_NON_CANONICAL_IN_SITEMAP` · erro · a partir do HTML gerado

Correção: liste só URLs canônicas no sitemap.

#### Sitemap indica uma página que não existe ou que redireciona [#sitemap-bad-url]

`BLUME_AUDIT_SITEMAP_BAD_URL` · erro · a partir do HTML gerado

Correção: remova a URL do sitemap ou gere a página que ele indica.

#### Sitemap tem erro de sintaxe ou formato incorreto [#sitemap-invalid]

`BLUME_AUDIT_SITEMAP_INVALID` · erro · a partir do HTML gerado

Correção: sitemaps devem ser XML válido no formato urlset ou sitemap index do sitemaps.org.

#### Sitemap excede 50 MB ou 50.000 URLs [#sitemap-too-large]

`BLUME_AUDIT_SITEMAP_TOO_LARGE` · erro · a partir do HTML gerado

Correção: divida o sitemap. Os limites são 50 MB e 50.000 URLs.

#### lastmod do sitemap é inválido ou está no futuro [#sitemap-lastmod-invalid]

`BLUME_AUDIT_SITEMAP_LASTMOD_INVALID` · aviso · a partir do HTML gerado

Correção: use uma data W3C real que não esteja no futuro. Quando um mecanismo de busca pega um sitemap mentindo sobre atualização, ele deixa de confiar no lastmod desse sitemap por completo.

#### Sitemap inclui URLs fora do seu escopo [#sitemap-out-of-scope]

`BLUME_AUDIT_SITEMAP_OUT_OF_SCOPE` · aviso · a partir do HTML gerado

Correção: um sitemap só pode listar URLs da sua própria origem.

#### Sitemap não está acessível [#sitemap-not-accessible]

`BLUME_AUDIT_SITEMAP_NOT_ACCESSIBLE` · erro · requer `--url`

Correção: deixe o sitemap.xml acessível na raiz do site.

### robots.txt

#### robots.txt ausente [#robots-missing]

`BLUME_AUDIT_ROBOTS_MISSING` · aviso · a partir do HTML gerado

Correção: defina `seo.robots: true` para gerar o robots.txt.

#### robots.txt tem erro de sintaxe [#robots-invalid]

`BLUME_AUDIT_ROBOTS_INVALID` · erro · a partir do HTML gerado

Correção: cada linha do robots.txt deve ser uma diretiva `Field: value` ou um comentário.

#### robots.txt bloqueia uma página que está no sitemap [#robots-disallows-indexable]

`BLUME_AUDIT_ROBOTS_DISALLOWS_INDEXABLE` · erro · a partir do HTML gerado

Correção: uma página não pode ser bloqueada no robots.txt e anunciada no sitemap ao mesmo tempo.

#### robots.txt bloqueia um crawler específico em páginas que estão no sitemap [#robots-blocks-crawler]

`BLUME_AUDIT_ROBOTS_BLOCKS_CRAWLER` · aviso · a partir do HTML gerado

Correção: restrinja ou remova a regra no grupo `User-agent` desse crawler se ele deve ler essas páginas. Se você bloqueou um crawler de IA de propósito, tudo bem: é só pular esta verificação.

Um crawler que tem o próprio grupo `User-agent` segue só esse grupo, então uma regra ali (`User-agent: GPTBot` seguido de `Disallow: /`) o bloqueia enquanto todos os outros crawlers leem a página. A auditoria reporta cada crawler uma vez, na regra que bloqueia a primeira página dele.

#### robots.txt não referencia o sitemap [#robots-sitemap-missing]

`BLUME_AUDIT_ROBOTS_SITEMAP_MISSING` · info · a partir do HTML gerado

Correção: defina `deployment.site` para que o robots.txt possa referenciar o sitemap.

#### robots.txt não está acessível [#robots-not-accessible]

`BLUME_AUDIT_ROBOTS_NOT_ACCESSIBLE` · erro · requer `--url`

Correção: deixe o robots.txt acessível na raiz do site.

### Descoberta por IA [#ai-discoverability]

#### llms.txt ausente do build [#llms-txt-missing]

`BLUME_AUDIT_LLMS_TXT_MISSING` · aviso · a partir do HTML gerado

Correção: gere o build de novo. `agents.llmsTxt` está ativado, mas o build não tem llms.txt. Se isso for intencional, defina `agents.llmsTxt: false`.

#### llms.txt lista uma página que o build não serve [#llms-txt-stale-entry]

`BLUME_AUDIT_LLMS_TXT_STALE_ENTRY` · aviso · a partir do HTML gerado

Correção: gere o build de novo para que o llms.txt corresponda ao site. Uma entrada desatualizada manda um agente de IA para uma página que não existe.

#### Página indexável ausente do llms.txt [#llms-txt-page-missing]

`BLUME_AUDIT_LLMS_TXT_PAGE_MISSING` · aviso · a partir do HTML gerado

Correção: gere o build de novo para que o llms.txt corresponda ao site. Se a página foi excluída de propósito, defina `ai.exclude: true` no front matter dela.

#### Nenhum registro de descoberta de agentes DNS-AID [#dns-aid-missing]

`BLUME_AUDIT_DNS_AID_MISSING` · info · requer `--url`

Correção: publique um registro SVCB ou HTTPS em ServiceMode em `_index._agents.<host>` no seu provedor de DNS para que agentes possam descobrir o site via DNS (DNS-AID).

#### Registros DNS-AID não são autenticados por DNSSEC [#dns-aid-unsigned]

`BLUME_AUDIT_DNS_AID_UNSIGNED` · info · requer `--url`

Correção: ative o DNSSEC para a zona para que resolvers com validação retornem respostas DNS-AID autenticadas. Se o seu provedor de DNS não oferece suporte a DNSSEC, os registros continuam funcionando sem assinatura.
