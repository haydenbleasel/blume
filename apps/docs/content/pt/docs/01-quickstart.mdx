Passe de uma pasta vazia a um site de documentação funcionando com apenas alguns comandos. O Blume precisa do **Node.js 22.12 ou superior** e de uma pasta `docs/` com pelo menos um arquivo `.md` ou `.mdx` — não há mais nada para configurar.

## Instalar e executar [#install-and-run]

<Steps>
  <Step title="Create a project">
    O `blume init` faz algumas perguntas — onde criar o projeto, qual o nome do
    seu site de documentação, que modelo usar e onde fica o seu conteúdo — e
    depois gera a estrutura mínima: uma pasta de conteúdo, um arquivo de
    configuração e um `package.json` com os scripts `dev`, `build` e `doctor`,
    além de um `.gitignore` que deixa `node_modules/`, o `.blume/` gerado,
    `dist/` e `.env.local` (onde ficam os segredos locais) fora do controle de
    versão. Ele instala as dependências com o gerenciador de pacotes que o
    executou. Passe `--yes` para pular as perguntas e aceitar os padrões, ou
    `--no-install` para apenas criar os arquivos.

    ```package-install
    npx blume init
    ```

    No pnpm 12, adicione `--allow-build=esbuild` depois de `pnpm dlx` (`pnpm dlx --allow-build=esbuild blume init`): o pnpm 12 se recusa a executar o script de instalação do esbuild, do qual o Astro depende, a menos que você o aprove. Dentro de um workspace pnpm já existente, a nova pasta precisa estar listada em `packages` do workspace (o pnpm não instala nada fora disso, então o `init` pula a instalação até que ela esteja listada), e o esbuild precisa de `allowBuilds: { esbuild: true }` no `pnpm-workspace.yaml` do workspace; o `init` lembra você das duas coisas. Com o Yarn 2 ou posterior, o `init` cria um `.yarnrc.yml` que muda o Yarn para uma instalação com `node_modules`, que é o que o Blume precisa; no Yarn 1, execute `npx blume init`.

    ```txt
    docs/
      index.mdx
    .gitignore
    blume.config.ts
    package.json
    ```

  </Step>
  <Step title="Start the dev server">
    No diretório do projeto, o Blume gera o runtime e serve a sua documentação
    com recarregamento automático.

    ```package-install
    npm run dev
    ```

  </Step>
  <Step title="Build for production">
    O HTML estático é gerado em `dist/`, com um índice de pesquisa local construído sobre ele.

    ```package-install
    npm run build
    ```

  </Step>
</Steps>

Vai adicionar o Blume a um projeto que já tem um `package.json`? O `blume init` não mexe nos arquivos existentes e pula a instalação, então instale o Blume você mesmo (`npm install blume`) e depois adicione `"dev": "blume dev"` e `"build": "blume build"` aos scripts dele, ou execute `npx blume dev` diretamente. Os próximos passos que o `init` exibe incluem os dois comandos para o seu gerenciador de pacotes.

:::tip
O Blume funciona com qualquer gerenciador de pacotes e nunca exige que você configure o Astro ou o Tailwind por conta própria.
:::

## Escrever a sua primeira página [#write-your-first-page]

Cada página é Markdown ou MDX com um pouco de frontmatter — o `title` e a `description` são exibidos automaticamente como o cabeçalho e a introdução da página. Coloque isso em `docs/index.mdx`:

```mdx docs/index.mdx lineNumbers
---
title: Introduction
description: Welcome to my docs.
---

Welcome! Use **Markdown** and built-in components — no imports required:

:::note
Blume ships callouts, cards, tabs, steps, and more.
:::
```

Salve o arquivo e o servidor de desenvolvimento recarrega na hora. A navegação, a pesquisa e os metadados das páginas são inferidos a partir dos seus arquivos à medida que você os adiciona — continue escrevendo, que o site acompanha.
