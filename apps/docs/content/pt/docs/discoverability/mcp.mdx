Hospede um servidor [Model Context Protocol](https://modelcontextprotocol.io) para que agentes de programação (Claude Code, Cursor, VS Code, conectores do claude.ai) possam buscar e ler sua documentação diretamente — sem scraping. É opcional:

```ts blume.config.ts lineNumbers
agents: {
  mcp: {
    enabled: true,
    route: "/mcp", // where the server is mounted
  },
}
```

| Opção | Padrão | Descrição |
| --- | --- | --- |
| `enabled` | `false` | Gera e hospeda o servidor MCP. |
| `route` | `/mcp` | Caminho em que o endpoint Streamable-HTTP é montado. |
| `name` | title | Nome do servidor exibido aos clientes (padrão: o título). |
| `instructions` | — | Dica de sistema opcional passada aos agentes que se conectam. |

Se uma página de conteúdo ou personalizada já ocupa essa rota, o servidor não é gerado: o build emite um aviso, e o `llms.txt` e os outros [documentos de descoberta](/docs/discoverability/agent-discovery) o deixam de fora.

## Ferramentas e recursos [#tools-and-resources]

O servidor expõe ferramentas somente leitura — `search_docs`, `get_page`, `list_pages` e `get_navigation` — e cada página como um recurso MCP (`resources/list` enumera as páginas em suas URLs servidas com o tipo `text/markdown`, deixando de fora as cópias de fallback de i18n das páginas não traduzidas, assim como `list_pages` faz; `resources/read` retorna o [Markdown para agentes](/docs/discoverability/markdown) da página, a mesma saída de `get_page`), então clientes que anexam contexto por URI podem navegar pela documentação sem chamar uma ferramenta. Ele publica documentos de descoberta em `/.well-known/mcp.json` e `/.well-known/mcp/server-card.json`. O server card segue o schema da extensão Server Card da [SEP-2127](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2127) (`name` em DNS reverso, endpoints de transporte `remotes`), com campos de compatibilidade no formato de initialize (`serverInfo`, `capabilities`, `transports`) para scanners construídos com base na revisão anterior da proposta. O menu **Connect to MCP** de cada página oferece instalação copiar-e-colar para Claude Code, Cursor, VS Code e Codex (exibido assim que [`deployment.site`](/docs/deployment) estiver definido).

`search_docs` roda seu próprio índice de texto completo, então funciona independentemente do seu provedor de [busca](/docs/configuration/search) — e até mesmo com `search: false`. O servidor MCP é um recurso separado da busca na página.

[Páginas ocultas](/docs/content/navigation#hidden-pages) ficam de fora de `list_pages` e `resources/list`, e de `search_docs` a menos que [`search.indexing.includeHiddenPages`](/docs/configuration/search#excluding-pages) esteja ativado, assim como ficam de fora da busca do site e do `llms.txt`. `get_page` e `resources/read` ainda retornam uma página oculta pela sua rota: oculta não quer dizer privada, e a página continua sendo servida na sua URL e como Markdown.

As mesmas ferramentas estão disponíveis via HTTP simples como a [API JSON](/docs/discoverability/json-api), para frameworks que não falam MCP.

O endpoint lê o corpo da requisição somente até 64 KB e responde a qualquer coisa maior com `413`. Uma chamada a uma ferramenta que não existe, ou com `arguments` que não sejam um objeto, recebe o erro Invalid params do JSON-RPC (`-32602`).

## Escopo por tipo de conteúdo e facetas [#scoping-by-content-type-and-facets]

`search_docs` e `list_pages` aceitam um filtro opcional `contentTypes`, restringindo os resultados a páginas dos [`type`s](/docs/content/frontmatter) de frontmatter informados — `["rfc"]`, `["blog", "changelog"]` — para que um agente trabalhando em um site que mistura documentação com RFCs, runbooks ou políticas consiga limitar a recuperação ao tipo de página de que precisa. Todo resultado informa seu tipo de conteúdo, e a saída de `list_pages` mostra os tipos em uso.

As duas ferramentas também aceitam um objeto `filters` que faz correspondência com as facetas que um site declara por tipo de conteúdo ([`content.types.<type>.facets`](/docs/configuration#frontmatter)) — chaves de frontmatter personalizadas cujos valores viram metadados filtráveis:

```json
{
  "query": "OpenAPI request schemas",
  "contentTypes": ["rfc"],
  "filters": { "domain": "architecture", "status": "enforced" }
}
```

Cada entrada de `filters` precisa corresponder (os resultados carregam seus valores de faceta, e `list_pages` mostra os de cada página), então uma base de conhecimento pode conduzir fluxos de trabalho de agentes com divulgação progressiva — enumerar os padrões aplicados, buscar somente dentro deles — sem nenhum servidor próprio.

Um valor precisa corresponder exatamente ao que `list_pages` mostra, incluindo maiúsculas e minúsculas: `"enforced"` não corresponde a uma página cujo `status` é `Enforced`. Valores de faceta são strings, então um número ou booleano em `filters` corresponde à sua forma em string (`{"priority": 1}` encontra `priority: 1`), e um valor de qualquer outro formato, como uma lista, é ignorado em vez de filtrar.

## Saída de servidor obrigatória [#server-output-required]

O servidor MCP é um endpoint ativo (`/mcp`), então não pode rodar em um build estático. Informe um adaptador de host de `blume/deploy` para mudar para a saída de servidor:

```ts blume.config.ts lineNumbers
import { node } from "blume/deploy"; // or vercel, netlify, cloudflare

export default defineConfig({
  deployment: node({ site: "https://docs.example.com" }),
});
```

Um build estático com `agents.mcp.enabled` falha imediatamente com uma mensagem pedindo que você defina um adaptador de host. Veja [Deployment](/docs/deployment) para os adaptadores. Depois de implantado, conecte-se pelo Claude Code com:

```bash
claude mcp add --transport http my-docs https://docs.example.com/mcp
```
