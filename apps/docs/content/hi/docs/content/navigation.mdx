Blume फ़ाइल सिस्टम से आपका साइडबार बनाता है, फिर आपको उसे जितना चाहें — या जितना कम चाहें — परिष्कृत करने देता है: पृष्ठ दर पृष्ठ, फ़ोल्डर दर फ़ोल्डर, या एक स्पष्ट config के साथ। ब्रेडक्रम्ब्स, पिछले/अगले लिंक, और पृष्ठ पर मौजूद आउटलाइन — सभी उसी मॉडल से निकलते हैं, जिसमें जोड़-तोड़ करने को कुछ नहीं होता।

## जनरेट किया गया साइडबार

डिफ़ॉल्ट रूप से साइडबार आपके कंटेंट ट्री को प्रतिबिंबित करता है:

- फ़ोल्डर **समूह** बन जाते हैं, फ़ाइलें **पृष्ठ** बन जाती हैं
- एक पृष्ठ का लेबल उसका frontmatter `title` होता है; एक समूह का लेबल मानव-पठनीय बनाया गया फ़ोल्डर नाम होता है
- आइटम पहले [संख्यात्मक उपसर्ग](/docs/content) के अनुसार, फिर वर्णानुक्रम में क्रमबद्ध होते हैं, और किसी फ़ोल्डर का `index` पृष्ठ सबसे पहले आता है

कई साइटों के लिए इतना ही काफ़ी है — नीचे दिया गया सब कुछ वैकल्पिक है।

## पृष्ठ लेबल, आइकन, और बैज

किसी एक पृष्ठ के साइडबार में दिखने के तरीके को उसके frontmatter से, `sidebar` के अंतर्गत, समायोजित करें:

```yaml lineNumbers
sidebar:
  label: Quickstart # override the title in the sidebar
  icon: rocket # an icon from Blume's built-in set
  badge: New # a small label beside the entry
  order: 1 # sort position within its group
```

पूरे पृष्ठ स्कीमा के लिए [Frontmatter](/docs/reference/frontmatter) देखें।

## फ़ोल्डर समूह

हर फ़ोल्डर एक साइडबार समूह बन जाता है। समूह का शीर्षक, आइकन, क्रम, और उसके चिल्ड्रन का क्रम सेट करने के लिए उसके पृष्ठों के साथ एक [`meta.ts`](/docs/content/meta) रखें:

```ts meta.ts
import { defineMeta } from "blume";

export default defineMeta({
  title: "Guides",
  icon: "book-open",
  pages: ["configuration", "theming", "deployment"],
});
```

हर फ़ील्ड और स्कैन समय पर meta की गणना करने के लिए [Folder meta](/docs/content/meta) देखें।

किसी फ़ोल्डर का `meta.title` और उसके अपने `index` पृष्ठ का frontmatter `title` स्वतंत्र रूप से हल किए जाते हैं — i18n के अंतर्गत एक का अनुवाद करना और दूसरे को भूल जाना एक सही साइडबार तो प्रस्तुत करता है पर लैंडिंग पृष्ठ पर ही पुराना `<title>`/शीर्षक छोड़ देता है। जब ये अलग होते हैं तो Blume एक `BLUME_NAV_INDEX_TITLE_MISMATCH` चेतावनी रिपोर्ट करता है। फ़ॉलबैक लोकेल से भरे गए अनूदित न किए गए पृष्ठ इससे मुक्त हैं — उनका शीर्षक फ़ॉलबैक लोकेल का है, और इसका समाधान पृष्ठ का अनुवाद करना है, न कि उसका frontmatter संपादित करना।

URL सेगमेंट जोड़े _बिना_ पृष्ठों को समूहबद्ध करने के लिए, कोष्ठक वाले फ़ोल्डर नाम का उपयोग करें — देखें [Pages](/docs/content#group-folders)।

## डिस्प्ले मोड

`navigation.sidebar.display` तय करता है कि हर साइडबार समूह कैसे प्रस्तुत होगा:

```ts blume.config.ts lineNumbers
navigation: {
  sidebar: {
    display: "flat", // "flat" | "group" | "page"
  },
}
```

- **`flat`** (डिफ़ॉल्ट) — एक ऐसा हेडर जो संकुचित नहीं होता, उसके पृष्ठ नीचे सूचीबद्ध होते हैं। जो पृष्ठ किसी समूह में नहीं हैं वे हमेशा पहले, समूह अनुभागों के ऊपर सूचीबद्ध होते हैं, ताकि उन्हें किसी समूह के चिल्ड्रन समझने की भूल न हो।
- **`group`** — प्रति समूह एक संकुचित होने योग्य `<details>` डिस्क्लोज़र। समूह डिफ़ॉल्ट रूप से संकुचित शुरू होते हैं; वर्तमान पृष्ठ वाला समूह हमेशा खुला शुरू होता है, ताकि केवल वही अनुभाग विस्तारित हो जिसमें आप हैं। किसी समूह को हर हाल में खुला रखने के लिए [फ़ोल्डर meta](/docs/content/meta) में `collapsed: false` सेट करें।
- **`page`** — हर समूह एक अकेली पंक्ति होती है जिस पर क्लिक करने पर साइडबार एक सब-पैनल में सरक जाता है जिसमें केवल उसी समूह के आइटम दिखते हैं, और शीर्ष पर एक बैक तीर होता है। पैनल रूट-सजग है, इसलिए समूह के भीतर किसी पृष्ठ पर सीधे पहुँचने पर वह सीधे उसी पर खुलता है।

:::tip
`page` मोड गहरे अनुभागों को सुव्यवस्थित रखता है — इसे तब चुनें जब समूहों में बहुत से चिल्ड्रन हों और आप उन्हें स्क्रॉल करके पार करने के बजाय उनमें भीतर जाना पसंद करें।
:::

[स्पष्ट साइडबार](#explicit-sidebar) में कोई समूह अपने स्वयं के `display` से वैश्विक मोड को ओवरराइड कर सकता है।

## क्रम निर्धारण

जब साइडबार जनरेट होता है, तो क्रम सर्वोच्च प्राथमिकता से शुरू करके हल किया जाता है:

<Steps>
  <Step title="Config saidbaar">
    एक स्पष्ट `navigation.sidebar` जनरेट किए गए ट्री को पूरी तरह प्रतिस्थापित कर
    देता है।
  </Step>
  <Step title="Folder meta">
    `meta.ts` में मौजूद `pages` सरणी एक समूह को क्रमबद्ध करती है।
  </Step>
  <Step title="Frontmatter">किसी पृष्ठ पर `sidebar.order`।</Step>
  <Step title="File system">
    पहले `index` पृष्ठ, फिर संख्यात्मक उपसर्ग, फिर लेबल के अनुसार वर्णानुक्रम।
  </Step>
</Steps>

एक ही स्पष्ट या संख्यात्मक क्रम पर आने वाले दो सहोदर आपस में वर्णानुक्रम पर लौट आते हैं — Blume एक `BLUME_DUPLICATE_SIDEBAR_ORDER` चेतावनी रिपोर्ट करता है ताकि यह बराबरी अनदेखी न रह जाए।

## छिपे हुए पृष्ठ

किसी पृष्ठ को साइडबार से — और पिछले/अगले पेजिनेशन से — छिपाएँ, जबकि वह बनता रहे और अपने URL से पहुँच योग्य रहे:

```yaml
sidebar:
  hidden: true
```

## टैब्स

शीर्ष-स्तरीय अनुभागों को हेडर में टैब के रूप में प्रस्तुत करें, जो किसी बड़ी साइट को अलग-अलग क्षेत्रों में बाँटने के लिए उपयोगी है — जैसे अडैप्टर, एक API, और AI गाइड। जब वर्तमान रूट किसी टैब के `path` के अंतर्गत आता है तो वह टैब हाइलाइट हो जाता है:

```ts blume.config.ts lineNumbers
navigation: {
  tabs: [
    { label: "Adapters", path: "/adapters", icon: "plug" },
    { label: "API", path: "/api", icon: "rocket" },
    { label: "AI", path: "/ai", icon: "sparkles" },
  ],
}
```

एक सक्षम किया गया [OpenAPI या AsyncAPI रेफ़रेंस](/docs/advanced/api-reference) अपने रूट पर माउंट होता है पर स्वयं कोई टैब नहीं जोड़ता — उसे हेडर में सामने लाने के लिए (और, नेटिव रेंडरर के लिए, उसके ऑपरेशन साइडबार को सीमित करने के लिए) एक टैब को उस रूट पर इंगित करें, जिस भी लेबल के साथ आप चाहें:

```ts blume.config.ts
navigation: {
  tabs: [
    { label: "API", path: "/reference" },
  ],
}
```

किसी टैब का `path` उसका अनुभाग उपसर्ग होता है, और वह लिंक लक्ष्य का भी काम करता है। ऐसा अनुभाग जिसका `path` स्वयं कोई पृष्ठ नहीं है — बिना `index.mdx` वाला फ़ोल्डर — 404 पर ले जाएगा, इसलिए टैब उसके बजाय अनुभाग के पहले पृष्ठ पर लौट जाता है। जब आप चाहें कि वह कहीं और पहुँचे तो `href` सेट करें:

```ts blume.config.ts
navigation: {
  tabs: [
    { label: "Changelog", path: "/changelog", href: "/changelog" },
  ],
}
```

यह उन रूट्स के लिए मायने रखता है जो कंटेंट ट्री का हिस्सा नहीं हैं, क्योंकि फ़ॉलबैक उन्हें नहीं देख सकता: जनरेट किया गया [changelog](/docs/advanced/changelog) इंडेक्स, या कोई [कस्टम पृष्ठ](/docs/advanced/custom-pages) जो आपने `pages/` के अंतर्गत जोड़ा है। `href` के बिना, एक `/changelog` टैब इंडेक्स के बजाय सबसे नई प्रविष्टि पर पहुँचता है। जो टैब `href` सेट नहीं करते वे अप्रभावित रहते हैं।

टैब **साइडबार को भी सीमित करते हैं**: जब वर्तमान रूट किसी टैब के `path` के अंतर्गत आता है, तो साइडबार केवल उसी अनुभाग के पृष्ठ दिखाता है — इसलिए `/adapters/*` अडैप्टर सूचीबद्ध करता है और कुछ नहीं। किसी टैब के `path` पर मौजूद फ़ोल्डर ही अनुभाग बन जाता है, इसलिए टैब्स के अलावा इसके लिए किसी अतिरिक्त config की ज़रूरत नहीं; अपने कंटेंट को प्रति टैब एक फ़ोल्डर में संरचित करें और हर टैब को उस पर इंगित करें।

ऐसे रूट पर जो किसी टैब के अंतर्गत नहीं है (या ऐसे टैब के अंतर्गत जिसका `path` `/` है), साइडबार वे पृष्ठ दिखाता है जो किसी टैब से संबंधित _नहीं_ हैं — हर टैब का फ़ोल्डर उससे छिपा दिया जाता है, क्योंकि उस अनुभाग का हेडर में पहले से ही अपना टैब है। इसलिए एक रूट लैंडिंग पृष्ठ आपके छिटपुट शीर्ष-स्तरीय पृष्ठ सूचीबद्ध करता है जबकि अनुभागों में बँटा कंटेंट अपने टैब के पीछे रहता है, जो Fumadocs के रूट फ़ोल्डरों को प्रतिबिंबित करता है। यदि किसी रूट के पास इस तरह दिखाने के लिए अपने कोई पृष्ठ नहीं हैं, तो उसके बजाय पूरा ट्री दिखाया जाता है, ताकि साइडबार कभी खाली न रहे।

## सिलेक्टर

साइट के पूरे-पूरे विभाजनों के बीच स्विच करने के लिए — कोई उत्पाद, कोई संस्करण, या गंतव्यों का कोई भी समूहबद्ध समुच्चय — एक `selector` जोड़ें। हर एक हेडर में ड्रॉपडाउन के रूप में प्रस्तुत होता है, और वह विकल्प दिखाता है जिसका `path` वर्तमान रूट से मेल खाता है:

```ts blume.config.ts lineNumbers
navigation: {
  selectors: [
    {
      kind: "version",
      label: "Version",
      items: [
        { label: "v2 (latest)", path: "/v2", icon: "rocket" },
        { label: "v1", path: "/v1" },
      ],
    },
  ],
}
```

हर आइटम एक `label`, एक `path`, और वैकल्पिक `icon`, `description`, और `tag` लेता है। `kind` (`dropdown`, `product`, `version`, या `language`) इस बात का संकेत है कि सिलेक्टर का उपयोग कैसे किया जाता है; सभी एक ही ड्रॉपडाउन प्रस्तुत करते हैं।

## विशेष रूप से प्रदर्शित लिंक

लिंक को साइडबार के शीर्ष पर, हर अनुभाग के ऊपर पिन करें — कोई ब्लॉग, कोई changelog, कोई संपर्क या सहायता पृष्ठ जो हमेशा एक क्लिक दूर होना चाहिए। जनरेट किए गए ट्री के विपरीत, ये विशेष लिंक **टैब द्वारा सीमित नहीं** होते: ये हर रूट पर, हर ब्रेकपॉइंट पर दिखते हैं।

```ts blume.config.ts lineNumbers
navigation: {
  featured: [
    { label: "Blog", href: "https://example.com/blog", icon: "newspaper" },
    { label: "Contact", href: "/contact", icon: "headphones" },
  ],
}
```

हर लिंक एक `label`, एक `href`, और एक वैकल्पिक `icon` लेता है (कोई [बिल्ट-इन आइकन](/docs/content/components#icon) नाम, इमेज पथ/URL, या इनलाइन SVG — जैसा कहीं और होता है वैसा ही)। कोई `href` कहीं भी इंगित कर सकता है: कोई बाहरी URL नए टैब में खुलता है, जबकि कोई आंतरिक रूट (`/contact`) बिल्ड समय पर आपके पृष्ठों के विरुद्ध सत्यापित किया जाता है, और कुछ भी मेल न खाने पर आपको चेतावनी देता है।

## स्पष्ट साइडबार

पूर्ण नियंत्रण के लिए, `navigation.sidebar` में स्पष्ट आइटम सूचीबद्ध करें — एक सीधी सरणी `sidebar.items` का संक्षिप्त रूप है, और ऑब्जेक्ट रूप उन्हें एक वैश्विक [`display`](#display-modes) के साथ जोड़ता है। जब आइटम सेट होते हैं, तो Blume उन्हें अक्षरशः उपयोग करता है और फ़ाइल-सिस्टम जनरेशन छोड़ देता है:

```ts blume.config.ts lineNumbers
navigation: {
  sidebar: [
    "/", // a page, referenced by route
    {
      label: "Guides", // a group
      collapsed: false,
      items: ["/configuration", "/configuration/theming"],
    },
    { label: "GitHub", href: "https://github.com/owner/repo" }, // an external link
  ],
}
```

हर आइटम एक पृष्ठ रूट (एक स्ट्रिंग), एक समूह (`label` + `items`), या एक लिंक (`label` + `href`) होता है। समूह नेस्ट हो सकते हैं, वैश्विक [`display` मोड](#display-modes) को ओवरराइड कर सकते हैं, और `collapsed` शुरू हो सकते हैं।

## रिपॉज़िटरी लिंक

जब आप अपने config में [`github`](/docs/configuration) सेट करते हैं, तो Blume हेडर में — थीम टॉगल के बगल में — एक GitHub आइकन दिखाता है जो आपकी रिपॉज़िटरी से लिंक करता है। यह डिफ़ॉल्ट रूप से चालू है; इसे `navigation.repo` से छिपाएँ:

```ts blume.config.ts lineNumbers
navigation: {
  repo: false, // hide the header GitHub link (default: true)
}
```

लिंक तभी दिखता है जब `github` कॉन्फ़िगर किया गया हो, इसलिए बिना रिपॉज़िटरी वाली परियोजनाएँ किसी भी तरह अप्रभावित रहती हैं।

## ब्रेडक्रम्ब्स और पेजिनेशन

ये साइडबार ट्री से मुफ़्त में मिलते हैं — कोई कॉन्फ़िगरेशन नहीं:

- **ब्रेडक्रम्ब्स** शीर्षक के ऊपर वर्तमान पृष्ठ का मूल समूह दिखाते हैं।
- हर पृष्ठ के नीचे **पिछला और अगला** लिंक साइडबार क्रम का अनुसरण करते हैं, और छिपे हुए पृष्ठों को छोड़ देते हैं।

## इस पृष्ठ पर

हर पृष्ठ के `##` और `###` शीर्षकों से एक दायीं-पट्टी आउटलाइन अपने आप जनरेट होती है, ताकि लंबे पृष्ठ भी नज़र दौड़ाने लायक बने रहें। संकरी स्क्रीनों पर, जहाँ दायीं पट्टी छिपी होती है, यह कंटेंट के ऊपर एक “इस पृष्ठ पर” ड्रॉपडाउन में सिमट जाती है।

## पृष्ठ क्रियाएँ

विषय-सूची के नीचे, हर पृष्ठ त्वरित क्रियाओं का एक सेट दिखाता है:

- **GitHub पर संपादित करें** — सीधे स्रोत फ़ाइल से लिंक करता है। आपके config में [`github`](/docs/configuration) सेट करते ही यह दिखने लगता है।
- **शीर्ष पर जाएँ** — लंबे पृष्ठों के शीर्ष पर सहजता से लौटाता है।
- **प्रतिक्रिया दें** — एक वैकल्पिक रिएक्शन और नोट के साथ पहले से भरा हुआ GitHub issue खोलता है (इसके लिए भी `github` आवश्यक है)।

अन्य क्रियाएँ पृष्ठ को AI टूल्स को सौंपती हैं — **Markdown के रूप में कॉपी करें** और **चैट में खोलें** — जिनका वर्णन [AI](/docs/configuration/ai#copy-as-markdown) में है।

[`export`](/docs/configuration/export) चालू होने पर, एक **निर्यात** क्रिया पाठकों को पृष्ठ को PDF या EPUB के रूप में डाउनलोड करने भी देती है।
