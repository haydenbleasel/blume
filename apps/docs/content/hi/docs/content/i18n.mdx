Blume एक प्रोजेक्ट को कई भाषाओं में परोसता है। अनूदित फ़ाइलों को सही जगह पर रखें और Blume आपके लिए रूटिंग, भाषा स्विचर, प्रति-लोकेल नेविगेशन और SEO जोड़ देता है — बनाए रखने के लिए कोई अलग रूटिंग लेयर नहीं है। यह ऑप्ट-इन है: `i18n` ब्लॉक के बिना, आपकी साइट ठीक पहले की तरह एकल-भाषा बनी रहती है।

## इसे सक्षम करें

अपने लोकेल और उनमें से कौन-सा डिफ़ॉल्ट है, यह सूचीबद्ध करते हुए एक `i18n` ब्लॉक जोड़ें:

```ts blume.config.ts lineNumbers
i18n: {
  defaultLocale: "en",
  locales: [
    { code: "en", label: "English" },
    { code: "fr", label: "Français" },
    { code: "ar", label: "العربية", dir: "rtl" },
  ],
}
```

हर लोकेल में एक `code` (URLs में उपयोग होता है), एक `label` (भाषा स्विचर में दिखता है), और दाएँ-से-बाएँ लिपियों के लिए एक वैकल्पिक `dir` होता है (डिफ़ॉल्ट रूप से `"ltr"`)।

## अनूदित सामग्री व्यवस्थित करें

डिफ़ॉल्ट लोकेल आपके कंटेंट रूट पर रहता है। हर दूसरा लोकेल अपने `code` के नाम वाला एक शीर्ष-स्तरीय फ़ोल्डर होता है, जो डिफ़ॉल्ट संरचना की नकल करता है:

```txt
docs/
  index.mdx               ->  /
  guides/quickstart.mdx   ->  /guides/quickstart
  fr/
    index.mdx             ->  /fr
    guides/quickstart.mdx ->  /fr/guides/quickstart
  ar/
    index.mdx             ->  /ar
```

| फ़ाइल                           | रूट                     |
| ------------------------------- | ----------------------- |
| `docs/index.mdx`                | `/`                     |
| `docs/guides/quickstart.mdx`    | `/guides/quickstart`    |
| `docs/fr/guides/quickstart.mdx` | `/fr/guides/quickstart` |

आप केवल वही फ़ाइलें अनूदित करते हैं जो आप चाहते हैं — बाकी सब अपने आप फ़ॉलबैक हो जाता है ([फ़ॉलबैक](#fallbacks) देखें)।

### फ़ाइलनाम प्रत्यय

अनुवादों को मूल के पास ही रखना पसंद करते हैं? `parser: "dot"` सेट करें और फ़ोल्डर उपयोग करने के बजाय फ़ाइलों को लोकेल प्रत्यय के साथ नाम दें:

```txt
docs/
  guides/quickstart.mdx     ->  /guides/quickstart      (default)
  guides/quickstart.fr.mdx  ->  /fr/guides/quickstart   (French)
```

विरल अनुवादों के लिए अच्छा है — पूरे ट्री की नकल किए बिना उन कुछ पृष्ठों को साथ रखें जिनका आपने अनुवाद किया है।

### साझा फ़ाइलें

ऐसी सामग्री के लिए जो हर भाषा में एक-सी है — एक चेंजलॉग, एक स्टेटस पेज — एक `$` मार्कर जोड़ें ताकि एक फ़ाइल बिना दोहराव के सभी लोकेल को परोस सके:

```txt
docs/changelog.$.mdx   ->  /changelog and /fr/changelog (same content)
docs/guides/meta.$.ts   (folder meta applied to every locale)
```

लोकेल-विशिष्ट `meta.ts` उस भाषा के लिए साझा वाले को अब भी ओवरराइड करता है।

## डिफ़ॉल्ट-लोकेल URLs

डिफ़ॉल्ट रूप से डिफ़ॉल्ट लोकेल का कोई URL उपसर्ग नहीं होता (`/`, `/guides/quickstart`) जबकि अन्य लोकेल उपसर्गित होते हैं (`/fr/…`)। इससे आपकी प्राथमिक भाषा के URLs साफ़ रहते हैं। हर लोकेल को, डिफ़ॉल्ट सहित, उपसर्ग देने के लिए:

```ts blume.config.ts lineNumbers
i18n: {
  // …
  hideDefaultLocalePrefix: false, // /en/…, /fr/…
}
```

## प्रति-लोकेल नेविगेशन

हर भाषा को उसका अपना साइडबार मिलता है, जो उस लोकेल की फ़ाइलों से बनता है — इसलिए अनुवाद संरचना, क्रम या लेबल में भिन्न हो सकते हैं। फ़ोल्डर [`meta.ts`](/docs/content/meta) फ़ाइलें भी प्रति लोकेल हल होती हैं: डिफ़ॉल्ट `dir` पार्सर के तहत, फ़्रेंच समूह को स्वतंत्र रूप से क्रमबद्ध करने के लिए `fr/guides/` के अंदर एक `meta.ts` रखें। `dot` पार्सर के तहत अनुवाद मूल के बगल में बैठते हैं, इसलिए किसी फ़ोल्डर का `meta.ts` हर लोकेल पर लागू होता है। [नेविगेशन](/docs/content/navigation) के बारे में बाकी सब कुछ, प्रति भाषा, वैसा ही काम करता है।

## फ़ॉलबैक

जब कोई पृष्ठ अभी तक अनूदित नहीं होता, तो Blume स्थानीयकृत URL पर फ़ॉलबैक लोकेल की सामग्री रेंडर करता है — इसलिए लिंक काम करता है, पृष्ठ पूरी तरह प्री-रेंडर होता है, और सर्च इंजन किसी मृत छोर पर नहीं भेजे जाते। फ़ॉलबैक डिफ़ॉल्ट रूप से आपका `defaultLocale` होता है:

```ts blume.config.ts lineNumbers
i18n: {
  // …
  fallbackLocale: "en", // default; set to null to 404 instead
}
```

फ़ॉलबैक पृष्ठ सर्च इंडेक्स से बाहर रखे जाते हैं और `hreflang` में असली अनुवाद के रूप में प्रचारित नहीं होते, इसलिए अनूदित न हुई सामग्री रैंकिंग के लिए प्रतिस्पर्धा नहीं करती। वे उस लोकेल के साइडबार में फिर भी दिखते हैं, इसलिए नेविगेशन पूरा रहता है — एक पाठक किसी भी भाषा में हर पृष्ठ तक पहुँच सकता है।

:::tip
अपने सबसे महत्वपूर्ण पृष्ठों — होमपेज, क्विकस्टार्ट और शीर्ष गाइड — का अनुवाद करके शुरुआत करें, और बाकी को फ़ॉलबैक होने दें। आप समय के साथ किसी भी लिंक को तोड़े बिना अनुवाद भरते जा सकते हैं।
:::

## एजेंट के साथ अनुवाद

आपको लोकेल हाथ से भरने की ज़रूरत नहीं है। [`blume translate`](/docs/reference/translate) हर उस पृष्ठ को ढूँढता है जो हर लोकेल में अनुपस्थित या पुराना है और उसे एक स्थानीय एजेंट CLI ([Claude Code](https://claude.com/claude-code) या [Codex](https://developers.openai.com/codex/cli)) से अनूदित करता है:

```bash
blume translate --claude
```

Blume हर परिणाम की संरचना — फ़्रंटमैटर, कोड फ़ेंस, लिंक — की पुष्टि करता है और फ़ाइलें स्वयं लिखता है; एजेंट केवल पाठ का अनुवाद करता है। एक कमिट किया गया लेजर (`blume.translations.json`) ट्रैक करता है कि हर अनुवाद किस स्रोत रिवीज़न से आया था, ताकि दोबारा चलाने पर केवल वही छुआ जाए जो बदला है, और जो अनुवाद आपने हाथ से लिखे हैं उन्हें जैसा है वैसा अपनाया जाता है, कभी ओवरराइट नहीं किया जाता। CI में, जब कोई स्रोत पृष्ठ अपने अनुवादों से आगे खिसक जाता है तो `blume translate --check` विफल हो जाता है।

## भाषा स्विचर

जब i18n चालू होता है, तो हेडर में अपने आप एक भाषा स्विचर दिखाई देता है, जो आपके `locales` से बनाया जाता है। हर पृष्ठ के लिए यह हर भाषा में मेल खाते अनुवाद को लिंक करता है; जहाँ अनुवाद अनुपस्थित है वहाँ यह फ़ॉलबैक पृष्ठ को लिंक करता है और उसे अनूदित-नहीं के रूप में चिह्नित करता है। कॉन्फ़िगर करने के लिए कुछ नहीं है।

## अनूदित UI

Blume अपने स्वयं के इंटरफ़ेस क्रोम के लिए अंतर्निहित अनुवाद भेजता है — “इस पृष्ठ पर”, “खोजें”, “GitHub पर संपादित करें”, और बाकी सब — इसलिए अंतर्निहित पैक वाले लोकेल को बॉक्स से ही अनूदित UI मिल जाता है। **आप केवल अपनी सामग्री का अनुवाद करते हैं।**

पैक 30 से अधिक भाषाओं के लिए उपलब्ध हैं — अरबी, बंगाली, बल्गेरियाई, कातालान, चीनी (सरलीकृत और पारंपरिक), क्रोएशियाई, चेक, डेनिश, डच, फ़िनिश, फ़्रेंच, जर्मन, ग्रीक, हिब्रू, हिन्दी, हंगेरियन, इंडोनेशियाई, इतालवी, जापानी, कोरियाई, नॉर्वेजियन, फ़ारसी, पोलिश, पुर्तगाली (और ब्राज़ीली पुर्तगाली), रोमानियाई, रूसी, सर्बियाई, स्लोवाक, स्पेनिश, स्वीडिश, थाई, तुर्की, यूक्रेनी और वियतनामी। ये समुदाय-अनुरक्षित हैं — कोई लोकेल जोड़ने या किसी अनुवाद को बेहतर बनाने के लिए एक PR खोलें।

अनुपस्थित या न भेजी गई स्ट्रिंग्स डिफ़ॉल्ट लोकेल पर, फिर अंग्रेज़ी पर फ़ॉलबैक करती हैं। किसी स्ट्रिंग को ओवरराइड करने या अपनी भाषा देने के लिए, लोकेल के अनुसार कुंजीबद्ध `i18n.ui` सेट करें:

```ts blume.config.ts lineNumbers
i18n: {
  // …
  ui: {
    fr: {
      search: { button: "Rechercher", placeholder: "Rechercher…" },
      page: { previous: "Précédent", next: "Suivant" },
    },
  },
}
```

## SEO

स्थानीयकृत SEO आपके लिए संभाल लिया जाता है — लिखने के लिए कोई प्रति-पृष्ठ मेटाडेटा नहीं:

- `<html lang>` और `dir` सक्रिय लोकेल से सेट होते हैं।
- `hreflang` वैकल्पिक किसी पृष्ठ के हर असली अनुवाद को लिंक करते हैं, साथ ही डिफ़ॉल्ट लोकेल की ओर इशारा करता एक `x-default` भी।
- कैनोनिकल URLs लोकेल-सही होते हैं, और JSON-LD में `inLanguage` होता है।

[`deployment.site`](/docs/deployment) सेट करें ताकि ये निरपेक्ष URLs के रूप में उत्सर्जित हो सकें।

## खोज

खोज सक्रिय भाषा तक सीमित होती है: किसी `/fr/…` पृष्ठ पर डायलॉग फ़्रेंच परिणाम लौटाता है, साथ में एक **सभी भाषाएँ** टॉगल होता है जिससे एक ही बार में हर लोकेल में खोजा जा सके। डिफ़ॉल्ट (Orama) और FlexSearch इंडेक्स ब्राउज़र में फ़िल्टर करते हैं; होस्टेड प्रदाता हर रिकॉर्ड पर एक `locale` फ़ैसेट रखते हैं।

## दाएँ-से-बाएँ

किसी लोकेल पर `dir: "rtl"` सेट करें और Blume पूरे इंटरफ़ेस को मिरर कर देता है — साइडबार, हेडर, विषय-सूची, पेजिनेशन, खोज और मेन्यू — और `<html dir>` को उसके अनुरूप सेट करता है। दो चीज़ें जानबूझकर बाएँ-से-दाएँ ही रहती हैं: **कोड ब्लॉक** (कोड किसी भी भाषा में LTR पढ़ा जाता है) और **फ़ॉलबैक सामग्री** — एक अनूदित न हुआ पृष्ठ उस भाषा की दिशा बनाए रखता है जिसमें वह वास्तव में लिखा गया है, ताकि RTL लोकेल के तहत दिखाई गई अंग्रेज़ी फिर भी सही पढ़ी जाए जबकि आसपास का क्रोम मिरर हो जाता है।
