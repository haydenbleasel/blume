Blume बॉक्स से बाहर ही एक चेंजलॉग के साथ आता है। हर रिलीज़ को एक सामान्य कंटेंट फ़ाइल के रूप में लिखें, उसे `type: changelog` से चिह्नित करें, और Blume हर एंट्री को एक जनरेट किए गए इंडेक्स पेज और एक RSS फ़ीड में इकट्ठा कर देता है — न कोई लेआउट बनाना है, न कोई सूची बनाए रखनी है। या फ़ाइलों को पूरी तरह छोड़ दें और [अपना चेंजलॉग GitHub Releases से लें](#from-github-releases)।

## एक एंट्री लिखें [#write-an-entry]

एक चेंजलॉग एंट्री एक सामान्य `.md` या `.mdx` पेज होती है जिसके फ़्रंटमैटर में `type: changelog` होता है। परंपरा के अनुसार वे `changelog/` के अंतर्गत रहती हैं, लेकिन जो मायने रखता है वह टाइप है — फ़ोल्डर नहीं:

```mdx changelog/v1-2-0.mdx lineNumbers
---
title: v1.2.0
type: changelog
date: 2026-06-20
changelog:
  version: 1.2.0
  category: Features
---

A big batch of components landed this release — columns, frames, trees, and tooltips, plus code groups that render as proper language tabs.

- New `Accordion`, `Expandable`, and `Tooltip` components
- `CodeGroup` tabs with flush code blocks
```

हर एंट्री को एक `date` दें ताकि इंडेक्स और फ़ीड नए से पुराने क्रम में सॉर्ट हों। बिना उद्धरण चिह्नों वाली YAML तिथि ठीक है — Blume उसे सामान्यीकृत कर देता है।

### `changelog` ऑब्जेक्ट [#the-changelog-object]

वैकल्पिक `changelog` ऑब्जेक्ट इंडेक्स और फ़ीड के लिए अधिक समृद्ध मेटाडेटा जोड़ता है:

<TypeTable
  type={{
    "changelog.version": {
      type: "string",
      description:
        "रिलीज़ संस्करण। जब कोई टाइटल न हो तो v-उपसर्ग वाले लेबल पर वापस चला जाता है।",
    },
    "changelog.category": {
      type: "string",
      description:
        "एंट्री के बगल में एक टैग के रूप में दिखाया जाता है, जैसे Release, Features, Fixes।",
    },
    "changelog.date": {
      type: "string",
      description:
        "प्रकाशन तिथि। यह यहाँ या शीर्ष स्तर पर हो सकती है — दोनों इंडेक्स और RSS फ़ीड को फ़ीड करते हैं।",
    },
  }}
/>

## इंडेक्स पेज [#the-index-page]

एक बार जब आपके पास कम से कम एक `type: changelog` एंट्री हो, तो Blume अपने आप एक **`/changelog`** पेज जनरेट कर देता है। यह एक केंद्रित, पूर्ण-चौड़ाई वाला इंडेक्स है — बिना साइडबार या विषय-सूची के — जो हर रिलीज़ को एक पंक्ति के रूप में सूचीबद्ध करता है, नई से पुरानी क्रम में और वर्ष के अनुसार समूहीकृत, ताकि एक लंबा इतिहास भी एक छोटा पेज बना रहे (उस आकार से काफ़ी कम जिसे एक एजेंट एक ही कॉन्टेक्स्ट विंडो में पढ़ सकता है):

- एंट्री का **title** पंक्ति का लेबल होता है — या जब कोई टाइटल न हो तो `v{version}`। यह उस एंट्री के अपने पेज से लिंक करता है, जहाँ रिलीज़ नोट्स पूरी तरह रेंडर होते हैं।
- `category` टाइटल के बगल में एक टैग के रूप में रेंडर होता है, ताकि पाठक एक नज़र में रिलीज़ और प्रीरिलीज़, या फ़ीचर्स और फ़िक्सेस के बीच अंतर कर सके।
- तिथि कॉन्फ़िगर किए गए [`dateFormat`](/docs/configuration#date-format) का पालन करती है, उस वर्ष को छोड़कर जिसे पंक्ति का समूह पहले से दिखाता है।
- ड्राफ़्ट और `sidebar.hidden` एंट्रियाँ छोड़ दी जाती हैं।

पेज का शीर्षक **Changelog** (अंग्रेज़ी में) होता है, जिसके नीचे एक पंक्ति का विवरण होता है। अपने कॉन्फ़िग में `changelog` के साथ अपना स्वयं का शीर्षक और विवरण सेट करें; ये पेज का `<title>`, मेटा विवरण और OG कार्ड भी बन जाते हैं, और `/changelog.md` पर उसके Markdown मिरर का शीर्ष भाग भी:

```ts blume.config.ts
changelog: {
  title: "Release notes",
  description: "Every Acme SDK release, newest first.",
},
```

दोनों ही, एक [हेडर टैब लेबल](/docs/content/i18n#per-locale-navigation) की तरह, लोकेल कोड से टेक्स्ट का एक मैप भी स्वीकार करते हैं। इंडेक्स डिफ़ॉल्ट लोकेल में रेंडर होता है, इसलिए यह उसी लोकेल की प्रविष्टि दिखाता है। यदि आप इनमें से किसी को सेट नहीं करते, तो वह अंतर्निर्मित टेक्स्ट ही बनाए रखता है, जिसे एक [UI स्ट्रिंग ओवरराइड](/docs/content/i18n#translated-ui) (`i18n.ui` के अंतर्गत `changelog.title` और `changelog.description`) बदल देता है।

यह पेज केवल तभी दिखाई देता है जब `/changelog` रूट पर पहले से कुछ न हो। इसे अपने स्वयं के डिज़ाइन से बदलने के लिए, `pages/changelog.astro` पर एक [कस्टम पेज](/docs/advanced/custom-pages) जोड़ें — वह नियंत्रण ले लेता है और Blume डिफ़ॉल्ट इंडेक्स जनरेट करना बंद कर देता है। `<Update>` कंपोनेंट, जिससे पिछली टाइमलाइन बनाई गई थी, अब भी ऐसे हाथ से लिखे गए पेज के लिए उपलब्ध है जिसमें रिलीज़ नोट्स इनलाइन चाहिए। यह MDX कंपोनेंट्स में से एक नहीं है, इसलिए इसे `.astro` पेज में ही इम्पोर्ट करें: `import Update from "blume/components/content/Update.astro";`।

`/changelog` की ओर इशारा करने वाला हेडर [टैब](/docs/content/navigation#tabs) इसी इंडेक्स को खोलता है — किसी `href` की आवश्यकता नहीं।

## GitHub Releases से [#from-github-releases]

एंट्रियाँ हाथ से लिखने के बजाय, अंतर्निर्मित [`githubReleases()` स्रोत](/docs/content/sources/github-releases) को किसी रेपो की ओर इंगित करें और हर रिलीज़ एक `type: changelog` एंट्री बन जाती है — वही टाइमलाइन और फ़ीड, सीधे उन रिलीज़ों से पोषित जिन्हें आप पहले से प्रकाशित करते हैं। Blume का अपना [चेंजलॉग](/changelog) इसी तरह बना है:

```ts blume.config.ts
import { filesystem, githubReleases } from "blume/sources";

content: {
  sources: [
    filesystem({ root: "content" }),
    githubReleases({
      prefix: "changelog",
      owner: "acme",
      repo: "sdk",
    }),
  ],
}
```

रिलीज़ का नाम टाइटल बन जाता है, उसका टैग `changelog.version` बन जाता है, और उसकी प्रकाशन तिथि टाइमलाइन को सॉर्ट करती है। हर रिलीज़ पेज को उसके नोट्स से सारांशित एक अद्वितीय मेटा विवरण भी मिलता है — मार्कडाउन हटाकर, सेक्शन हेडिंग्स और चेंजसेट कमिट-हैश उपसर्ग हटाकर, उस सर्च-स्निपेट लंबाई तक काटकर जिसकी जाँच [`blume audit`](/docs/cli/audit) करता है — बजाय साइट विवरण पर वापस जाने के। एक निजी रेपो `GITHUB_TOKEN` एनवायरनमेंट वेरिएबल से प्रमाणित होता है। हर विकल्प के लिए [GitHub Releases](/docs/content/sources/github-releases) देखें।

## RSS फ़ीड [#the-rss-feed]

Blume **`/changelog/rss.xml`** पर एक चेंजलॉग फ़ीड भी बनाता है, जो `date` के अनुसार नए से पुराने क्रम में सॉर्ट होती है। फ़ीड्स को एक निरपेक्ष साइट URL की आवश्यकता होती है, इसलिए [`deployment.site`](/docs/deployment) सेट करें; तब Blume हर पेज पर एक `<link rel="alternate">` टैग इंजेक्ट करता है ताकि पाठक इसे अपने आप खोज सकें।

फ़ीड डिफ़ॉल्ट रूप से चालू है। इसे [`seo.rss`](/docs/discoverability/rss) के अंतर्गत ट्यून करें:

```ts blume.config.ts lineNumbers
seo: {
  rss: {
    enabled: true,
    types: ["blog", "changelog"],
    limit: 50,
  },
}
```

टाइमलाइन को रखते हुए फ़ीड छोड़ने के लिए `rss.types` से `"changelog"` हटा दें।

## स्ट्रक्चर्ड डेटा [#structured-data]

जब [स्ट्रक्चर्ड डेटा](/docs/discoverability/structured-data) चालू होता है, तो हर चेंजलॉग एंट्री को उसके विवरण और प्रकाशन तिथि के साथ एक schema.org **`TechArticle`** के रूप में उत्सर्जित किया जाता है, ताकि सर्च इंजन रिलीज़ों को तिथि-युक्त लेखों के रूप में इंडेक्स कर सकें।
