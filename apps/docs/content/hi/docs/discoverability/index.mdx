description: >-
  एक Blume साइट कैसे खोजी जाती है — एक ओर सर्च इंजन और सोशल प्लेटफ़ॉर्म द्वारा, दूसरी ओर कोडिंग एजेंट और AI असिस्टेंट द्वारा — और प्रत्येक सतह कहाँ कॉन्फ़िगर की जाती है।
---

सर्च इंजन और AI एजेंट आपके दस्तावेज़ों से एक ही चीज़ चाहते हैं: एक स्वच्छ, मशीन-पठनीय विवरण कि प्रत्येक पृष्ठ क्या कहता है, पृष्ठ आपस में कैसे संबंधित हैं, और उन्हें कौन प्रकाशित करता है। Blume दोनों को एक ही खोज-योग्यता परत के रूप में मानता है। मेटाडेटा, सोशल कार्ड, फ़ीड, और संरचित डेटा उन क्रॉलर की सेवा करते हैं जो आपको रैंक करते हैं; `llms.txt`, कच्चा Markdown, एक JSON API, एक MCP सर्वर, और डिस्कवरी मैनिफ़ेस्ट उन एजेंटों की सेवा करते हैं जो आपके बारे में प्रश्नों के उत्तर देते हैं — और इनके बीच की फ़ाइलें (`robots.txt`, साइटमैप, JSON-LD) दोनों द्वारा पढ़ी जाती हैं।

इनमें से लगभग सब कुछ डिफ़ॉल्ट रूप से चालू है और इसे किसी कॉन्फ़िगरेशन की आवश्यकता नहीं है। नियंत्रण `blume.config.ts` में दो कुंजियों के अंतर्गत रहते हैं: सर्च इंजन और सोशल प्लेटफ़ॉर्म जो देखते हैं उसके लिए `seo`, और एजेंट जो देखते हैं उसके लिए `agents`।

```ts blume.config.ts lineNumbers
seo: {
  og: { enabled: true },
  rss: { enabled: true, types: ["blog", "changelog"] },
  sitemap: true,
  robots: true,
  structuredData: true,
  x: { handle: "@acme" },
},
agents: {
  llmsTxt: true,
  mcp: { enabled: false },
},
```

इसमें से अधिकांश एक निरपेक्ष साइट URL के साथ अधिक प्रभावी होता है — [`deployment.site`](/docs/deployment) सेट करें ताकि फ़ीड, OG छवियाँ, कैनोनिकल, साइटमैप, JSON-LD, और प्रत्येक एजेंट मैनिफ़ेस्ट पूर्ण URL उत्सर्जित कर सकें। कुछ सतहें — Open Graph छवियाँ, साइटमैप, RSS फ़ीड, और AI कैटलॉग — तब तक बंद रहती हैं जब तक यह सेट नहीं किया जाता।

## बिल्ड क्या उत्सर्जित करता है [#what-the-build-emits]

| सतह | कहाँ | डिफ़ॉल्ट | गाइड |
| --- | --- | --- | --- |
| `<head>` मेटाडेटा, कैनोनिकल, X कार्ड | प्रत्येक पृष्ठ | चालू | [मेटाडेटा](/docs/discoverability/metadata) |
| सोशल शेयर छवियाँ | `/og/<route>.png` | साइट URL के साथ चालू | [Open Graph छवियाँ](/docs/discoverability/open-graph) |
| schema.org JSON-LD | प्रत्येक पृष्ठ | चालू | [संरचित डेटा](/docs/discoverability/structured-data) |
| RSS फ़ीड | `/<type>/rss.xml` | साइट URL के साथ चालू | [RSS फ़ीड](/docs/discoverability/rss) |
| `sitemap.xml`, `robots.txt`, कंटेंट सिग्नल | साइट रूट | चालू | [साइटमैप और robots](/docs/discoverability/sitemap-and-robots) |
| `llms.txt`, `llms-full.txt` | साइट रूट | चालू | [llms.txt](/docs/discoverability/llms-txt) |
| कच्चे Markdown मिरर, कंटेंट नेगोशिएशन, Copy as Markdown, Open in chat | `/<route>.md` | चालू | [एजेंटों के लिए Markdown](/docs/discoverability/markdown) |
| JSON API और इसका OpenAPI विवरण | `/api/docs/…`, `/openapi.json` | चालू | [JSON API](/docs/discoverability/json-api) |
| MCP सर्वर | `/mcp` | ऑप्ट-इन, सर्वर आउटपुट | [MCP सर्वर](/docs/discoverability/mcp) |
| `agent-readability.json`, `Link` हेडर, API कैटलॉग, AI कैटलॉग (ARD), WebMCP | साइट रूट, `/.well-known/…` | चालू | [एजेंट डिस्कवरी](/docs/discoverability/agent-discovery) |
| एजेंट स्किल्स, Web Bot Auth कुंजियाँ | `/.well-known/…` | ऑप्ट-इन | [एजेंट डिस्कवरी](/docs/discoverability/agent-discovery#skills-discovery) |

प्रत्येक उत्पन्न फ़ाइल उस फ़ाइल के लिए स्थान छोड़ देती है जिसे आप स्वयं शिप करते हैं: `public/` में एक `robots.txt`, `sitemap.xml`, `llms.txt`, `openapi.json`, या `agent-readability.json` रखें और Blume उसके स्थान पर आपकी फ़ाइल सर्व करता है।

पृष्ठ के भीतर मौजूद **असिस्टेंट** वह एकमात्र AI सुविधा है जिसका दस्तावेज़ीकरण अन्यत्र है: यह एक खोज सतह के बजाय पाठक-सम्मुख उत्पाद सुविधा है, इसलिए यह `ai` के अंतर्गत कॉन्फ़िगर की जाती है और [कॉन्फ़िगरेशन](/docs/configuration/assistant) के अंतर्गत रहती है।

## अपने काम की जाँच करना [#checking-your-work]

[`blume audit`](/docs/cli/audit) बनी हुई साइट को क्रॉल करता है और शीर्षकों, विवरणों, कैनोनिकल, Open Graph और X कार्ड, hreflang, साइटमैप, `robots.txt`, और संरचित डेटा पर रिपोर्ट करता है। प्रतिक्रिया हेडर, कॉन्फ़िगर किए गए रीडायरेक्ट, और [DNS-आधारित एजेंट डिस्कवरी](/docs/discoverability/agent-discovery#dns-based-discovery-dns-aid) की भी जाँच करने के लिए इसे `--url` के साथ किसी डिप्लॉयमेंट की ओर इंगित करें।
