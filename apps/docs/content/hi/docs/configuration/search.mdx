Blume बिना किसी होस्टेड इंफ्रास्ट्रक्चर और बिना API कुंजियों के लोकल खोज के साथ आता है। यह ब्राउज़र में चलता है, `blume dev` और `blume build` दोनों में काम करता है, और केवल आपकी वास्तविक सामग्री को इंडेक्स करता है — नेविगेशन क्रोम और बाहर रखे गए पृष्ठ छोड़ दिए जाते हैं। जब यह आपके लिए छोटा पड़ने लगे, तो आप खोज के दिखने या व्यवहार को बदले बिना किसी होस्टेड या सिमेंटिक बैकएंड पर स्विच कर सकते हैं — केवल आपके द्वारा कॉन्फ़िगर किया गया `search.provider` बदलता है।

Blume, Fumadocs के प्रोवाइडर सेट के बराबर पहुँचता है: **Orama**, **FlexSearch**, **Algolia**, **Orama Cloud**, **Typesense**, और **Mixedbread** (साथ ही **Pagefind**)। केवल कॉन्फ़िगर किए गए प्रोवाइडर का SDK ही आपके प्रोजेक्ट में इंस्टॉल होता है, इसलिए एक बैकएंड चुनने से बाकी कभी शामिल नहीं होते।

## खोज का उपयोग

खोज को <Badge variant="accent">⌘K</Badge> (या `Ctrl K`) से खोलें, या जब आप किसी फ़ील्ड में टाइप नहीं कर रहे हों तो `/` दबाएँ। `Esc` इसे बंद करता है, और `⌘J` (या `Ctrl J`) परिणाम पूर्वावलोकन पैनल को टॉगल करता है।

क्वेरियाँ पृष्ठ के **शीर्षक**, **विवरण**, और **मुख्य पाठ** से मेल खाती हैं, जिसमें शीर्षक मेल सबसे ऊपर रैंक होते हैं और विवरण मुख्य पाठ से ऊपर।

## लोकप्रिय पृष्ठ

पाठक द्वारा कोई क्वेरी टाइप करने से पहले, खोज संवाद एक **लोकप्रिय** सूची दिखाता है। डिफ़ॉल्ट रूप से यह पहले छह साइडबार पृष्ठ होते हैं — जो कई टैब वाली साइटों पर अक्सर गलत सेक्शन सामने ला देता है। इसके बजाय अपनी पसंद के लिंक पिन करें:

```ts blume.config.ts lineNumbers
search: {
  popular: [
    { href: "/guides/getting-started", icon: "rocket", label: "Getting started" },
    { href: "/guides/install", icon: "download", label: "Install" },
    { href: "/concepts/overview", label: "Overview" },
  ],
},
```

प्रत्येक प्रविष्टि एक `href` (आंतरिक रूट या बाहरी URL) और एक `label` लेती है, साथ ही एक वैकल्पिक `icon` — लेबल के बगल में दिखाया गया एक अंतर्निर्मित आइकन नाम, जो डिफ़ॉल्ट रूप से एक फ़ाइल ग्लिफ़ होता है। साइडबार फ़ॉलबैक बनाए रखने के लिए `popular` को छोड़ दें या खाली रहने दें।

Blume में अन्य जगहों के आइकनों के विपरीत, यहाँ `icon` एक अंतर्निर्मित नाम ही होना चाहिए: ये पंक्तियाँ एक क्लाइंट आइलैंड में रेंडर होती हैं, इसलिए इमेज पाथ या इनलाइन SVG समर्थित नहीं है और यह फ़ाइल ग्लिफ़ पर वापस आ जाता है।

`href` इस तरह लिखें मानो साइट रूट पर माउंट हो — `basePath` आपके लिए लागू किया जाता है, ठीक वैसे ही जैसे `navigation.featured` के लिए। बाहरी URL बिना बदलाव के पास होते हैं।

<Callout type="warning">
  एक क्यूरेटेड सूची लिंक का एक ही सेट होती है जो हर भाषा में साझा होती है। जिस
  साइट पर `i18n` कॉन्फ़िगर है, वहाँ साइडबार फ़ॉलबैक पाठक की लोकेल का अनुसरण करता
  है, लेकिन `popular` प्रविष्टियाँ वहीं इंगित करती हैं जहाँ उनका `href` कहता है
  — इसलिए लोकेल-उपसर्ग वाले रूट केवल तभी पिन करें जब आप चाहते हों कि हर पाठक उसी
  एक भाषा में भेजा जाए।
</Callout>

## क्या इंडेक्स होता है

हर इंडेक्स-योग्य पृष्ठ के लिए, Blume उसका शीर्षक, विवरण, और सादे पाठ में घटाया गया मुख्य पाठ इंडेक्स करता है — कोड ब्लॉक, इमेज, और मार्कअप हटा दिए जाते हैं, ताकि परिणाम प्रासंगिक बने रहें। इंडेक्स आपकी स्रोत फ़ाइलों से बनता है, इसलिए यह dev और production में एक समान होता है।

## टैग

किसी पृष्ठ के फ्रंटमैटर में `search.tags` जोड़ें ताकि उसे खोज संवाद में एक फ़िल्टर के अंतर्गत समूहित किया जा सके — पाठक एक क्लिक से परिणामों को किसी टैग तक सीमित कर सकते हैं। टैग होस्टेड प्रोवाइडरों पर एक फ़ैसेट भी बन जाते हैं।

```yaml
search:
  tags: [api, reference]
```

## प्रोवाइडर

क्लाइंट-साइड प्रोवाइडर कुंजी-रहित हैं और उन्हें किसी अतिरिक्त कॉन्फ़िग की ज़रूरत नहीं है। होस्टेड वाले `blume.config.ts` में **सार्वजनिक** क्रेडेंशियल लेते हैं (ब्राउज़र तक भेजना सुरक्षित है) और अपनी **गुप्त** एडमिन कुंजी बिल्ड-टाइम पर एक एनवायरनमेंट वेरिएबल से पढ़ते हैं — गुप्त कुंजी कभी कॉन्फ़िग या क्लाइंट बंडल में नहीं पहुँचती।

### Orama (डिफ़ॉल्ट)

Blume का डिफ़ॉल्ट इंजन। यह `/blume-search.json` पर सर्व किया जाने वाला एक JSON इंडेक्स बनाता है और उसे ब्राउज़र में क्वेरी करता है — तत्काल, क्लाइंट-साइड, और `blume dev` में आपके संपादन करते ही लाइव। कोई कुंजी नहीं, कोई सेवा नहीं।

```ts blume.config.ts lineNumbers
search: {
  provider: "orama", // default
}
```

#### बिना रिक्त स्थान के लिखी जाने वाली भाषाएँ

Orama का मानक टोकनाइज़र उन शब्द-सीमाओं पर विभाजन करता है जो केवल स्पेस से अलग होने वाली लिपियों में मौजूद हैं, इसलिए जापानी, चीनी, कोरियाई, और थाई पाठ अन्यथा कोई मेल ही नहीं देते। Blume यह आपके लिए संभालता है: जब [`i18n.defaultLocale`](/docs/content/i18n) इनमें से कोई भाषा हो, तो इंडेक्स एक शब्द-विभाजक टोकनाइज़र पर स्विच हो जाता है (जो ब्राउज़र- और Node-नेटिव `Intl.Segmenter` पर बना है)। बस अपनी साइट की भाषा घोषित करना पर्याप्त है:

```ts blume.config.ts lineNumbers
i18n: {
  defaultLocale: "ja",
  locales: [{ code: "ja", label: "日本語" }],
}
```

वही टोकनाइज़र खोज संवाद, MCP सर्वर के `search_docs` टूल, और Ask AI ग्राउंडिंग की सेवा करता है। मिश्रित-भाषा वाली साइट पर पूरा इंडेक्स डिफ़ॉल्ट लोकेल का टोकनाइज़र साझा करता है — यह सुरक्षित है, क्योंकि लैटिन शब्द विभाजन के बाद भी अक्षुण्ण रहते हैं, इसलिए अंग्रेज़ी (या किसी भी स्पेस वाली भाषा) के पृष्ठ डिफ़ॉल्ट भाषा के साथ-साथ खोजे जा सकते रहते हैं।

जापानी और चीनी एक कदम और आगे जाते हैं। केवल विभाजन करने पर एक संयुक्त पद उसके हिस्सों के रूप में इंडेक्स होता है — 資金決済法 को 資金, 決済 और 法 के रूप में — जिससे वह पृष्ठ जो कहीं-कहीं हर हिस्से का उल्लेख करता है, उस पृष्ठ से ऊपर रैंक कर सकता है जो वास्तव में उस पद के बारे में है। इसलिए हान, हीरागाना और काताकाना को अतिव्यापी अक्षर-युग्मों के रूप में इंडेक्स किया जाता है, और उन इंडेक्सों पर की गई क्वेरियाँ उन पृष्ठों को वरीयता देती हैं जिनमें किसी पद के युग्म एक साथ हों, और जब कोई पृष्ठ उन सभी को न रखता हो तो किसी-भी-युग्म मेल तक ढील दे देती हैं, ताकि पूरा वाक्य टाइप करने पर भी उसके सबसे निकट पृष्ठ लौटें। कोरियाई और थाई अपने विभाजित शब्द बनाए रखते हैं।

### FlexSearch

एक दूसरा कुंजी-रहित, क्लाइंट-साइड विकल्प। यह वही `/blume-search.json` इंडेक्स पुनः उपयोग करता है जो Orama भेजता है और ब्राउज़र में एक [FlexSearch](https://github.com/nextapps-de/flexsearch) डॉक्यूमेंट इंडेक्स बनाता है। `blume dev` और `blume build` में काम करता है।

FlexSearch में कोई समकक्ष सेगमेंटेशन हुक नहीं है, इसलिए जापानी, चीनी, कोरियाई, या थाई में बनी साइटों के लिए Orama (डिफ़ॉल्ट) या [Pagefind](#pagefind) को प्राथमिकता दें, जिसका `pagefind_extended` बाइनरी उन भाषाओं को मूल रूप से विभाजित करता है।

```ts blume.config.ts lineNumbers
search: {
  provider: "flexsearch",
}
```

### Pagefind

बहुत बड़े डॉक्स के लिए, [Pagefind](https://pagefind.app) चुनें। यह आपके बिल्ट HTML को इंडेक्स करता है और इंडेक्स को माँग पर शार्ड्स में लोड करता है, जिससे साइट चाहे कितनी भी बड़ी हो जाए, आरंभिक पेलोड बहुत छोटा रहता है।

```ts blume.config.ts lineNumbers
search: {
  provider: "pagefind",
}
```

Pagefind केवल `blume build` के दौरान चलता है, इसलिए इस प्रोवाइडर के साथ `blume dev` में खोज उपलब्ध नहीं होती।

### Algolia

ब्राउज़र आपकी search-only कुंजी के साथ सीधे [Algolia](https://www.algolia.com) को क्वेरी करता है। हर `blume build` `ALGOLIA_ADMIN_API_KEY` से ली गई एडमिन कुंजी का उपयोग करके इंडेक्स को बदल देता है (यदि यह सेट नहीं है तो बिल्ड चेतावनी देता है और अपलोड छोड़ देता है)। हर सिंक पर पूरा इंडेक्स बदल दिया जाता है, इसलिए जिन पृष्ठों को आप हटाते या नाम बदलते हैं, वे बासी परिणामों के रूप में नहीं रह जाते।

```ts blume.config.ts lineNumbers
search: {
  provider: "algolia",
  algolia: {
    appId: "YOUR_APP_ID",
    indexName: "docs",
    searchApiKey: "YOUR_SEARCH_ONLY_KEY", // public
  },
}
```

### Orama Cloud

होस्टेड Orama। ब्राउज़र सार्वजनिक API कुंजी के साथ आपके इंडेक्स एंडपॉइंट को क्वेरी करता है; `blume build` `ORAMA_PRIVATE_API_KEY` का उपयोग करके इंडेक्स में रिकॉर्ड पुश करता है। सिंक सक्षम करने के लिए `indexId` सेट करें।

```ts blume.config.ts lineNumbers
search: {
  provider: "orama-cloud",
  oramaCloud: {
    endpoint: "https://cloud.orama.run/v1/indexes/your-index",
    apiKey: "YOUR_PUBLIC_API_KEY",
    indexId: "your-index-id", // for the build-time sync
  },
}
```

### Typesense

स्व-होस्टेड या क्लाउड [Typesense](https://typesense.org)। ब्राउज़र search-only कुंजी के साथ कलेक्शन को क्वेरी करता है; `blume build` `TYPESENSE_ADMIN_API_KEY` का उपयोग करके कलेक्शन को फिर से बनाता है और डॉक्यूमेंट इम्पोर्ट करता है। हर सिंक पर कलेक्शन हटाकर दोबारा बनाया जाता है ताकि हटाए या नाम बदले गए पृष्ठ बासी परिणामों के रूप में न रह जाएँ — यदि आप कलेक्शन की सेटिंग्स को हाथ से ट्यून करते हैं, तो बिल्ड के बाद उन्हें दोबारा लागू करें।

```ts blume.config.ts lineNumbers
search: {
  provider: "typesense",
  typesense: {
    host: "xyz.a1.typesense.net",
    collection: "docs",
    searchApiKey: "YOUR_SEARCH_ONLY_KEY", // public
    // port + protocol default to 443 / https
  },
}
```

### Mixedbread

[Mixedbread](https://www.mixedbread.com) के माध्यम से सिमेंटिक खोज। क्वेरियाँ एक जनरेट किए गए `/api/search` एंडपॉइंट के ज़रिए प्रॉक्सी की जाती हैं जो आपकी कुंजी रखता है, इसलिए इस प्रोवाइडर के लिए **सर्वर आउटपुट आवश्यक है** (`deployment.output: "server"`)। एंडपॉइंट `MIXEDBREAD_API_KEY` पढ़ता है। अपनी सामग्री को अपने बिल्ड में Mixedbread CLI से स्टोर में सिंक करें, जैसे `mxbai vs sync <STORE_ID> ./content --ci`।

```ts blume.config.ts lineNumbers
search: {
  provider: "mixedbread",
  mixedbread: {
    storeId: "YOUR_STORE_ID",
  },
}
```

### खोज अक्षम करना

```ts blume.config.ts lineNumbers
search: {
  provider: "none",
}
```

## पृष्ठ बाहर रखना

केवल इंडेक्स-योग्य पृष्ठ ही खोजे जाते हैं। जब कोई पृष्ठ फ्रंटमैटर में `search.exclude` सेट करता है, तो उसे इंडेक्स से बाहर रखा जाता है:

```yaml
search:
  exclude: true
```

[छिपे हुए पृष्ठ](/docs/content/navigation#hidden-pages) भी डिफ़ॉल्ट रूप से बाहर रखे जाते हैं। फिर भी उन्हें इंडेक्स करने के लिए, यह विकल्प चुनें:

```ts blume.config.ts lineNumbers
search: {
  indexing: { includeHiddenPages: true },
}
```
