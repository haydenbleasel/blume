---
title: Analytics
description: First-party web analytics — PostHog, Google Analytics, Plausible, Mixpanel, Segment, and more — as adapters in blume.config.ts.
---

Blume injects analytics for you from an `analytics` list in `blume.config.ts`. Each entry is an adapter imported from `blume/analytics`: one per provider, plus `script()` for anything without one.

```ts blume.config.ts lineNumbers
import { defineConfig } from "blume";
import { googleAnalytics, plausible, posthog, vercel } from "blume/analytics";

export default defineConfig({
  analytics: [
    posthog({ key: "phc_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" }),
    vercel(),
    googleAnalytics({ id: "G-XXXXXXXXXX" }),
    plausible({ domain: "docs.example.com" }),
  ],
});
```

Adapters emit into `<head>` in the order you list them, and you can combine as many as you like. Every adapter is plain data: what it returns is validated with the rest of your config and inlined into the built site, so it can carry any JSON value but never a function. A passthrough option that JSON can't carry (a function, `undefined`, a bigint) fails validation with its path rather than disappearing from the build.

Analytics loads in **production builds only**. The scripts are emitted by `blume build`, never by `blume dev`, so local traffic never reaches your dashboards and you don't need a separate "development" project.

:::note
Analytics is opt-in. With no `analytics` list (or an empty one), Blume injects nothing.
:::

Every identifier below — a project key, a measurement ID, a site token — is the public, browser-side one from the provider's own install snippet. Each adapter renders that snippet, so it's safe to commit to your docs repository; Blume never asks for a secret.

Blume's docs use a client-side router, so most navigation is an in-page swap rather than a full page load. Every adapter counts those as pageviews: providers whose script follows history changes on its own need nothing extra, and for the ones that only count real loads (PostHog, Segment, Hightouch) Blume sends the pageview itself. The two exceptions are the tag managers — [Google Tag Manager](#google-tag-manager) and [Adobe](#adobe-analytics) load a container whose own rules decide what fires, so give it a history-change trigger.

## PostHog

Pass your **project API key** to `posthog()` to add [PostHog](https://posthog.com). The host defaults to PostHog Cloud US; set `host` for EU Cloud (`https://eu.i.posthog.com`) or a self-hosted instance.

```ts blume.config.ts lineNumbers
analytics: [
  posthog({
    key: "phc_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    host: "https://us.i.posthog.com", // optional, this is the default
  }),
],
```

`key` and `host` are the two options Blume maps (`host` becomes `api_host`). Anything else you pass — `persistence`, `capture_pageview`, `autocapture`, `disable_session_recording`, and every other `posthog.init` option — is forwarded to `posthog.init` verbatim.

Blume sends a `$pageview` for each client-router navigation only while PostHog captures page loads alone, which is its behavior when you set neither `capture_pageview` nor `defaults`. With `capture_pageview: "history_change"`, or a `defaults` date such as `"2025-05-24"` from PostHog's current snippet, PostHog captures navigations itself, so Blume sends nothing extra. With `capture_pageview: false`, no pageviews are sent at all.

## Vercel Web Analytics

Add `vercel()` to include [Vercel Web Analytics](https://vercel.com/docs/analytics). Blume renders Vercel's official Astro component, which injects the first-party script served from your own domain once Web Analytics is enabled for the project in the Vercel dashboard.

```ts blume.config.ts lineNumbers
analytics: [vercel()],
```

No keys are needed — the script reports to the project it's deployed under. This only collects data on Vercel deployments, where the `/_vercel/insights` endpoint exists. Any option you pass is forwarded to the component as a prop (`mode`, `debug`, `endpoint`, `scriptSrc`, …); `beforeSend` is a function and can't travel through config, so assign `window.webAnalyticsBeforeSend` from a `script()` adapter instead.

## Cloudflare Web Analytics

[Cloudflare Web Analytics](https://developers.cloudflare.com/web-analytics/) has two setups, and only one of them needs an adapter.

**Proxied zone (automatic setup).** If Cloudflare serves your site — a Worker with a custom domain, Pages, or any zone with the orange cloud on — enable Web Analytics for the zone in the Cloudflare dashboard and stop there. Cloudflare injects the beacon at the edge, so leave `cloudflare()` out; listing it as well would count every pageview twice.

**Any other host (manual setup).** For a site Cloudflare doesn't proxy, add the site under Web Analytics in the dashboard, copy the token out of the JS snippet it gives you (the `token` inside `data-cf-beacon`), and pass it here. Blume renders the same beacon tag the snippet does.

```ts blume.config.ts lineNumbers
analytics: [
  cloudflare({
    token: "0123456789abcdef0123456789abcdef",
  }),
],
```

The whole option object becomes the beacon's `data-cf-beacon` JSON, so any other beacon setting (`spa`, …) passes straight through.

## Google Analytics 4

Pass the **measurement ID** of your GA4 web data stream (`G-…`, under the stream's details in the property's Admin → Data Streams) to `googleAnalytics()`. Blume renders the Google tag exactly as the stream's install instructions do: the async `gtag.js` loader plus the `dataLayer` bootstrap and `config` call.

```ts blume.config.ts lineNumbers
analytics: [
  googleAnalytics({
    id: "G-XXXXXXXXXX",
    anonymize_ip: true, // optional: any other `config` parameter
  }),
],
```

`id` is the one option Blume maps. Anything else you pass rides on the `gtag('config', …)` call verbatim (`send_page_view`, `cookie_domain`, `debug_mode`, …). GA4's enhanced measurement counts history changes as page views by default, so client-side navigations are tracked without any extra setup. Google Analytics takes a day or two to show new data; the [Google Analytics Debugger](https://chrome.google.com/webstore/detail/google-analytics-debugger/jnkmfdileelhofjcijamephohjechhna) extension shows requests as they happen.

## Google Tag Manager

Pass your **container ID** (`GTM-…`, shown in the workspace header) to `googleTagManager()`. Blume renders the `<head>` half of the container snippet; the `<noscript>` iframe is for browsers without JavaScript, which never run analytics anyway.

```ts blume.config.ts lineNumbers
analytics: [
  googleTagManager({
    id: "GTM-XXXXXXX",
    dataLayer: "dataLayer", // optional, this is the default
  }),
],
```

Which tags fire, and on what, is the container's configuration. Client-side navigations reach the container as history changes, so fire pageview tags from a **History Change** trigger rather than the page-load one. Cookie consent banners are yours to set up in the container too.

## Plausible

Pass the **domain** you added in [Plausible](https://plausible.io) to `plausible()`. For a self-hosted or proxied instance, set `host` to its origin; the default is Plausible Cloud.

```ts blume.config.ts lineNumbers
analytics: [
  plausible({
    domain: "docs.example.com",
    host: "https://plausible.example.com", // optional, defaults to https://plausible.io
  }),
],
```

`domain` becomes `data-domain` and `host` picks where `/js/script.js` loads from. Any other option becomes its own `data-` attribute on the tag (`api: "/api/event"` → `data-api`). Script variants with extra behavior baked into the filename (`script.outbound-links.js`, …) are a different tag; load those with [`script()`](#custom-scripts).

## Fathom

Pass your **site ID** (from the site's script settings in [Fathom](https://usefathom.com)) to `fathom()`.

```ts blume.config.ts lineNumbers
analytics: [
  fathom({
    site: "ABCDEFGH",
    "honor-dnt": "true", // optional: any other `data-` setting
  }),
],
```

`site` becomes `data-site`. Any other option becomes its own `data-` attribute on the tag (`honor-dnt`, `excluded-domains`, `canonical`, …), as strings. `spa` defaults to `"auto"` so Fathom counts the client router's navigations; pass your own `spa` value to override it.

## Pirsch

Pass your **identification code** (Settings → Developer → Identification Code in [Pirsch](https://pirsch.io)) to `pirsch()`.

```ts blume.config.ts lineNumbers
analytics: [
  pirsch({
    code: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  }),
],
```

`code` becomes `data-code`, and Blume gives the tag the `pianjs` id Pirsch's script finds itself by. Any other option becomes its own `data-` attribute (`dev`, `exclude`, `include`, `domain`, `endpoint`, …).

## Databuddy

Pass your **client ID** (from the website's settings in [Databuddy](https://databuddy.cc)) to `databuddy()`.

```ts blume.config.ts lineNumbers
analytics: [
  databuddy({
    clientId: "xxxxxxxxxxxxxxxxxxxxx",
    "track-web-vitals": "true", // optional: any other `data-` setting
    "skip-patterns": '["/admin/*"]',
  }),
],
```

`clientId` becomes `data-client-id`. Any other option becomes its own `data-` attribute on the tag, so name it the way the attribute reads, in kebab-case (`track-web-vitals`, `track-errors`, `track-outgoing-links`, `api-url`, …). Databuddy ignores a camelCase name like `trackWebVitals`. Values are strings: `"true"` or `"false"` for a switch, and a JSON array for `skip-patterns` and `mask-patterns`. Databuddy reads any other list value as empty.

## OneDollarStats

Add the site's domain in [OneDollarStats](https://onedollarstats.com), then list `oneDollarStats()`. It needs no key, because OneDollarStats matches events to a site by the domain they come from.

```ts blume.config.ts lineNumbers
analytics: [oneDollarStats()],
```

Each option becomes its own `data-` attribute on the tag, and values are strings:

- `hostname` reports every event under that host name (`docs.example.com`, with no `https://` or path) on every host, not just `localhost`, so preview deploys and staging count as that site's traffic. Leave it unset unless every build should report under that name.
- `devmode: "true"` together with `hostname` lets a local `blume preview` send events. On `localhost` the tracker sends nothing without both, so keep them out of the committed config.
- `url` is the collector endpoint events are posted to (`https://collector.onedollarstats.com/events` by default), not the site's URL.
- `autocollect: "false"` turns off automatic page views.
- `"hash-routing": "true"` sends a page view on every navigation, even when only the `#fragment` changes, like a table-of-contents click. Blume leaves the attribute off for `"false"`, because the tracker turns hash routing on whenever it's present.

## Mixpanel

Pass your **project token** (project settings → Access Keys in [Mixpanel](https://mixpanel.com)) to `mixpanel()`. If the project uses EU or India data residency, set `region` to match, or Mixpanel drops the events.

```ts blume.config.ts lineNumbers
analytics: [
  mixpanel({
    token: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    region: "eu", // optional: "us" (default), "eu", or "in"
  }),
],
```

`token` and `region` are the options Blume maps (`region` becomes `api_host`). Blume also sets `track_pageview` to `"url-with-path-and-query-string"`, so the library tracks each navigation itself. Anything else you pass — including `track_pageview` — is forwarded to `mixpanel.init` verbatim (`persistence`, `autocapture`, `record_sessions_percent`, …).

## Amplitude

Pass your **project API key** (project settings in [Amplitude](https://amplitude.com)) to `amplitude()`. Blume renders the Browser SDK's script-loader snippet: the keyed SDK bundle plus the `init` call.

```ts blume.config.ts lineNumbers
analytics: [
  amplitude({
    key: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    serverZone: "EU", // optional: any other `init` option
  }),
],
```

`key` is the one option Blume maps. The `init` options start from what the dashboard snippet ships — `autocapture: true` and `fetchRemoteConfig: true` — and anything else you pass is merged over them verbatim. Autocapture covers page views and history changes, so client-side navigations count.

## Segment

Pass the **write key** of your JavaScript source in [Segment](https://segment.com) to `segment()`. If you serve analytics.js from a [custom domain](https://segment.com/docs/connections/sources/custom-domain/) to sidestep ad blockers, set `cdn` to that origin.

```ts blume.config.ts lineNumbers
analytics: [
  segment({
    key: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    cdn: "https://cdn.example.com", // optional, defaults to https://cdn.segment.com
  }),
],
```

`key` and `cdn` are the options Blume maps: the snippet loads the library from `cdn` and tells it to fetch its integrations from there too. Anything else you pass is forwarded as the `analytics.load` options verbatim (`integrations`, …).

## Hightouch

Pass the **write key** of your event source in [Hightouch](https://hightouch.com) to `hightouch()`. The events API host defaults to the US East region; set `host` (without a scheme) if your workspace uses another.

```ts blume.config.ts lineNumbers
analytics: [
  hightouch({
    key: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    host: "us-east-1.hightouch-events.com", // optional, this is the default
  }),
],
```

`key` and `host` are the options Blume maps (`host` becomes `apiHost`). Anything else you pass is forwarded as the `htevents.load` options verbatim.

## Heap

Pass your **app ID** (the environment ID under the project's install settings in [Heap](https://heap.io)) to `heap()`.

```ts blume.config.ts lineNumbers
analytics: [
  heap({
    id: "1234567890",
    disableTextCapture: true, // optional: any other `heap.load` option
  }),
],
```

`id` is the one option Blume maps. Anything else you pass becomes the config object of `heap.load` verbatim.

## Hotjar

Pass your **site ID** (the number in the site's tracking code in [Hotjar](https://hotjar.com)) to `hotjar()`.

```ts blume.config.ts lineNumbers
analytics: [
  hotjar({
    id: 1234567,
    version: 6, // optional, this is the default
  }),
],
```

`id` is `hjid` and `version` is `hjsv` in Hotjar's tracking code; the adapter takes nothing else.

## Microsoft Clarity

Pass your **project ID** (from the project's tracking code in [Clarity](https://clarity.microsoft.com)) to `clarity()`.

```ts blume.config.ts lineNumbers
analytics: [
  clarity({
    id: "xxxxxxxxxx",
  }),
],
```

The adapter takes nothing else; Clarity's settings live in its dashboard.

## LogRocket

Pass your **app ID** (`org/app`, from the project settings in [LogRocket](https://logrocket.com)) to `logrocket()`. Blume renders the install snippet: the SDK plus the guarded `LogRocket.init` call.

```ts blume.config.ts lineNumbers
analytics: [
  logrocket({
    id: "your-org/your-app",
    release: "1.2.0", // optional: any other `init` option
  }),
],
```

`id` is the one option Blume maps. Anything else you pass is forwarded to `LogRocket.init` verbatim (`release`, `console`, `network`, `dom`, …). A request or response sanitizer is a function and can't travel through config; for those, drop the adapter and call `LogRocket.init` yourself from a [`script()`](#custom-scripts) adapter.

## Clearbit

Pass your **publishable API key** (`pk_…`) to `clearbit()`. Blume renders the Clearbit tag, which loads whatever tags — Reveal, forms — you manage in Clearbit.

```ts blume.config.ts lineNumbers
analytics: [
  clearbit({
    key: "pk_xxxxxxxxxxxxxxxx",
  }),
],
```

The adapter takes nothing else.

## Adobe Analytics

Pass the **embed script URL** of your Launch (Adobe Experience Platform Tags) environment to `adobe()`. Copy it from the environment's install instructions under Environments in Data Collection; the production one looks like `https://assets.adobedtm.com/…/launch-….min.js`.

```ts blume.config.ts lineNumbers
analytics: [
  adobe({
    url: "https://assets.adobedtm.com/xxxxxxxx/launch-xxxxxxxx.min.js",
  }),
],
```

Blume loads the script asynchronously; what it tracks is the property's rules. Client-side navigations don't reload the page, so give the property a rule on history changes (or call `_satellite.track` from a [`script()`](#custom-scripts) adapter).

## Custom scripts

Use `script()` to load any provider without an adapter, or a provider's tag in a form its adapter doesn't render. Each one renders one `<script>` tag and must set **exactly one** of `src` (external) or `content` (inline).

```ts blume.config.ts lineNumbers
analytics: [
  // Umami
  script({
    src: "https://cloud.umami.is/script.js",
    strategy: "defer",
    attributes: { "data-website-id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" },
  }),
  // An inline snippet
  script({
    content: "console.log('analytics ready')",
  }),
],
```

`attributes` is a map of extra HTML attributes (`data-*`, `id`, …) spread onto the tag, and `strategy` adds `async` or `defer` to external scripts.

## Custom events

Blume's page feedback sends a custom event through every configured adapter that has a client API — PostHog, Mixpanel, Heap, Segment, Hightouch, Amplitude, LogRocket, Adobe, Google Analytics, Google Tag Manager (as a `{ event }` push on `window.dataLayer`), Plausible, Databuddy, Fathom, OneDollarStats (with each property value as a string), Pirsch, Clarity, Hotjar, and Vercel. Cloudflare and Clearbit have no event API. Every event also fires as a `blume:track` CustomEvent on `window` with `{ event, props }` in `detail`, so a `script()` adapter can forward it anywhere else. For deploying your built site, see [Deployment](/docs/deployment).
