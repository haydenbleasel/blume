  APIキー不要ですぐに使えるクライアントサイド検索に加え、ドキュメントの成長に合わせて切り替えられるホスト型・セマンティック型のバックエンドも用意しています。
---

Blume にはホスト型インフラも API キーも不要なローカル検索が同梱されています。ブラウザ上で動作し、`blume dev` と `blume build` の両方で機能し、実際のコンテンツだけをインデックス化します — ナビゲーションの装飾や除外されたページはスキップされます。手狭になったら、検索の見た目や挙動を変えずにホスト型やセマンティック型のバックエンドへ切り替えられます — 変わるのは設定する `search.provider` だけです。

Blume は Fumadocs のプロバイダー群と同等の構成を備えています: **Orama**、**FlexSearch**、**Algolia**、**Orama Cloud**、**Typesense**、**Mixedbread**（さらに **Pagefind**）。設定したプロバイダーの SDK だけがプロジェクトにインストールされるため、あるバックエンドを選んでも他のものが引き込まれることはありません。

## 検索を使う

<Badge variant="accent">⌘K</Badge>（または `Ctrl
K`）で検索を開くか、入力欄にフォーカスしていないときに `/` を押します。`Esc`
で閉じ、`⌘J`（または `Ctrl J`）で結果プレビューペインを切り替えられます。

クエリはページの**タイトル**、**説明**、**本文テキスト**にマッチし、タイトルのマッチが最上位、説明が本文より上位にランク付けされます。

## 人気ページ

読者がクエリを入力する前に、検索ダイアログは**人気**リストを表示します。デフォルトではサイドバーの最初の6ページですが、複数タブのサイトでは誤ったセクションが表示されがちです。代わりに、表示したいリンクをピン留めしましょう:

```ts blume.config.ts lineNumbers
search: {
  popular: [
    { href: "/guides/getting-started", icon: "rocket", label: "Getting started" },
    { href: "/guides/install", icon: "download", label: "Install" },
    { href: "/concepts/overview", label: "Overview" },
  ],
},
```

各エントリは `href`（内部ルートまたは外部 URL）と `label` を取り、さらに任意の `icon` — ラベルの横に表示される組み込みアイコン名で、デフォルトはファイルのグリフ — を指定できます。`popular` を省略するか空のままにすると、サイドバーのフォールバックが維持されます。

Blume の他の場所のアイコンとは異なり、ここでの `icon` は組み込み名である必要があります: これらの行はクライアントアイランドとしてレンダリングされるため、画像パスやインライン SVG はサポートされず、ファイルのグリフにフォールバックします。

`href` は、サイトがルートにマウントされているかのように記述してください — `navigation.featured` と同様に、`basePath` は自動的に適用されます。外部 URL はそのまま通過します。

<Callout type="warning">
  キュレーションされたリストは、すべての言語で共有される単一のリンク集です。`i18n`
  を設定したサイトでは、サイドバーのフォールバックは読者のロケールに従いますが、
  `popular` のエントリは `href` が指す先へ遷移します —
  すべての読者を特定の1言語へ
  送りたい場合にのみ、ロケール接頭辞付きのルートをピン留めしてください。
</Callout>

## インデックス対象

インデックス可能なすべてのページについて、Blume はそのタイトル、説明、そしてプレーンテキストに還元された本文をインデックス化します — コードブロック、画像、マークアップは取り除かれるため、結果の関連性が保たれます。インデックスはソースファイルから構築されるため、開発環境と本番環境で同一です。

## タグ

ページのフロントマターに `search.tags` を追加すると、検索ダイアログ内のフィルターでグループ化されます — 読者はクリック1つで結果をタグで絞り込めます。タグはホスト型プロバイダーではファセットにもなります。

```yaml
search:
  tags: [api, reference]
```

## プロバイダー

クライアントサイドのプロバイダーはキー不要で、追加の設定は必要ありません。ホスト型のものは `blume.config.ts` で**公開**認証情報（ブラウザに配布しても安全なもの）を受け取り、**シークレット**の管理キーはビルド時に環境変数から読み込みます — シークレットが設定ファイルやクライアントバンドルに含まれることはありません。

### Orama（デフォルト）

Blume のデフォルトエンジンです。`/blume-search.json` で提供される JSON インデックスを構築し、ブラウザ上でクエリします — 即座に、クライアントサイドで動作し、`blume dev` では編集中もライブで反映されます。キーもサービスも不要です。

```ts blume.config.ts lineNumbers
search: {
  provider: "orama", // default
}
```

#### 空白で区切らない言語

Orama の標準トークナイザーは、空白区切りの文字体系にしか存在しない単語境界で分割するため、そのままでは日本語、中国語、韓国語、タイ語のテキストはまったくマッチしません。Blume はこれを自動的に処理します: [`i18n.defaultLocale`](/docs/content/i18n) がこれらの言語のいずれかである場合、インデックスは単語分割トークナイザー（ブラウザおよび Node ネイティブの `Intl.Segmenter` を基盤とするもの）に切り替わります。サイトの言語を宣言するだけで済みます:

```ts blume.config.ts lineNumbers
i18n: {
  defaultLocale: "ja",
  locales: [{ code: "ja", label: "日本語" }],
}
```

同じトークナイザーが検索ダイアログ、MCP サーバーの `search_docs` ツール、そして Ask AI のグラウンディングに使われます。多言語混在のサイトでは、インデックス全体がデフォルトロケールのトークナイザーを共有します — ラテン文字の単語は分割を経ても無傷で残るため、これは安全です。英語（あるいは空白区切りの任意の言語）のページも、デフォルト言語と並んで検索可能なままです。

日本語と中国語では、さらに一歩進んだ処理を行います。分割だけでは複合語がその構成要素としてインデックス化され — 資金決済法 が 資金、決済、法 として扱われ — 各要素をどこかで言及しているだけのページが、その語を実際に扱っているページより上位に来てしまう可能性があります。そのため、漢字、ひらがな、カタカナは重なり合う文字ペアとしてインデックス化され、これらのインデックスへのクエリでは、語のペアをまとめて含むページが優先されます。すべてを含むページがない場合は、いずれかのペアにマッチする方式へ緩和されるため、文章全体を入力しても最も近いページが返ってきます。韓国語とタイ語は分割された単語のままです。

### FlexSearch

キー不要のクライアントサイドの選択肢がもう1つあります。Orama が提供するのと同じ `/blume-search.json` インデックスを再利用し、ブラウザ上で [FlexSearch](https://github.com/nextapps-de/flexsearch) のドキュメントインデックスを構築します。`blume dev` と `blume build` の両方で動作します。

FlexSearch には同等の分割フックがないため、日本語、中国語、韓国語、タイ語のサイトでは Orama（デフォルト）か、`pagefind_extended` バイナリがこれらの言語をネイティブに分割する [Pagefind](#pagefind) を選ぶとよいでしょう。

```ts blume.config.ts lineNumbers
search: {
  provider: "flexsearch",
}
```

### Pagefind

非常に大規模なドキュメントには [Pagefind](https://pagefind.app) を選択できます。ビルド済みの HTML をインデックス化し、インデックスをシャード単位でオンデマンドに読み込むため、サイトがどれだけ大きくなっても初期ペイロードは小さいままです。

```ts blume.config.ts lineNumbers
search: {
  provider: "pagefind",
}
```

Pagefind は `blume build` の間しか実行されないため、このプロバイダーでは `blume dev` で検索を利用できません。

### Algolia

ブラウザは検索専用キーで [Algolia](https://www.algolia.com) に直接クエリします。`blume build` のたびに `ALGOLIA_ADMIN_API_KEY` の管理キーを使ってインデックスが置き換えられます（未設定の場合、ビルドは警告を出してアップロードをスキップします）。同期のたびにインデックス全体が置き換えられるため、削除したりリネームしたりしたページが古い結果として残り続けることはありません。

```ts blume.config.ts lineNumbers
search: {
  provider: "algolia",
  algolia: {
    appId: "YOUR_APP_ID",
    indexName: "docs",
    searchApiKey: "YOUR_SEARCH_ONLY_KEY", // public
  },
}
```

### Orama Cloud

ホスト型の Orama です。ブラウザは公開 API キーでインデックスのエンドポイントにクエリし、`blume build` は `ORAMA_PRIVATE_API_KEY` を使ってレコードをインデックスに送信します。同期を有効にするには `indexId` を設定してください。

```ts blume.config.ts lineNumbers
search: {
  provider: "orama-cloud",
  oramaCloud: {
    endpoint: "https://cloud.orama.run/v1/indexes/your-index",
    apiKey: "YOUR_PUBLIC_API_KEY",
    indexId: "your-index-id", // for the build-time sync
  },
}
```

### Typesense

セルフホストまたはクラウドの [Typesense](https://typesense.org) です。ブラウザは検索専用キーでコレクションにクエリし、`blume build` は `TYPESENSE_ADMIN_API_KEY` を使ってコレクションを作り直しドキュメントをインポートします。同期のたびにコレクションが削除・再構築されるため、削除やリネームしたページが古い結果として残ることはありません — コレクションの設定を手動で調整している場合は、ビルド後に再適用してください。

```ts blume.config.ts lineNumbers
search: {
  provider: "typesense",
  typesense: {
    host: "xyz.a1.typesense.net",
    collection: "docs",
    searchApiKey: "YOUR_SEARCH_ONLY_KEY", // public
    // port + protocol default to 443 / https
  },
}
```

### Mixedbread

[Mixedbread](https://www.mixedbread.com) によるセマンティック検索です。クエリはキーを保持する生成済みの `/api/search` エンドポイント経由でプロキシされるため、このプロバイダーは**サーバー出力**（`deployment.output: "server"`）を**必要とします**。エンドポイントは `MIXEDBREAD_API_KEY` を読み込みます。ビルド内で Mixedbread CLI を使ってコンテンツをストアに同期してください。例: `mxbai vs sync <STORE_ID> ./content --ci`。

```ts blume.config.ts lineNumbers
search: {
  provider: "mixedbread",
  mixedbread: {
    storeId: "YOUR_STORE_ID",
  },
}
```

### 検索を無効にする

```ts blume.config.ts lineNumbers
search: {
  provider: "none",
}
```

## ページを除外する

検索対象はインデックス可能なページのみです。フロントマターで `search.exclude` を設定すると、そのページはインデックスから除外されます:

```yaml
search:
  exclude: true
```

[非表示ページ](/docs/content/navigation#hidden-pages)もデフォルトで除外されます。それでもインデックス化したい場合は、次のようにオプトインしてください:

```ts blume.config.ts lineNumbers
search: {
  indexing: { includeHiddenPages: true },
}
```
