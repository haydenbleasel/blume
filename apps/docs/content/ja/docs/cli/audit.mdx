[`blume validate`](/docs/cli/validate) は _コンテンツ_ を読み取りますが、`blume audit` は _ビルド済みのサイト_ を読み取ります。ビルド後に `dist/` 内の HTML をクロールし、SEO とサイトの健全性に関する問題を報告します。対象は、タイトル、メタディスクリプション、canonical、Open Graph と X のカード、見出し、hreflang、画像、サイトマップ、`robots.txt`、構造化データです。

サイトをビルドしたのは Blume なので、各指摘にはクローラーから見える URL だけでなく、修正すべきソースファイル **とフロントマターの行** も示されます。

```
⚠ Meta description too long or too short   5 pages
    /docs/configuration/export    content/docs/configuration/export.mdx:3
    fix: Rewrite `description` in the frontmatter to fit the length range.
```

ビルド後に実行します。

```bash
blume build
blume audit
```

指摘はページごとに並ぶのではなく、チェックごとにまとめて表示されます。そのため、レポートは ToDo リストのように読めます。`--verbose` を使うと影響を受けるすべてのページを詳細付きで展開できます。`--only`/`--skip` を使うと、1 カテゴリずつ対処できます。`blume audit --list-checks` はチェックの全カタログを出力します。内容はこのページ末尾の [チェックカタログ](#check-catalog) と同じで、各指摘の `docsUrl` はそのカタログ内の該当項目にリンクしています。

## フラグ [#flags]

- `--fail-on error|warning|info` — CI のゲートです。この重大度以上の指摘があると、0 以外の終了コードで終了します。デフォルトは `error` です。`--strict` は `--fail-on warning` のエイリアスです。
- `--url <origin>` — 稼働中のデプロイにもリクエストを送り、ステータスコード、レスポンスヘッダー、設定したリダイレクトを確認します。
- `--external` — 外部リンクをネットワーク経由で確認します。
- `--ignore <glob>` — `--external` と併用し、URL が glob に一致する外部リンクを確認の対象から外します（例：`--ignore "https://api.acme.example/**"`）。複数のパターンを指定するには、このフラグを繰り返します。一致の判定方法は [`blume validate --ignore`](/docs/cli/validate#flags) と同じです。内部リンクは常にチェックされます。
- `--only <check|category>` / `--skip <check|category>` — レポートの対象を指定したチェックやカテゴリだけに絞り込むか、それらを除外します（カンマ区切り）。どのチェックにもカテゴリにも当てはまらない語を指定するとエラーになり、最も近い候補が提案されます。そのため、タイプミスでレポートが気づかないうちに空になることはありません。
- `--list-checks` — 監査が報告できるすべてのチェックを出力して終了します。
- `--verbose` — 最初の数件だけでなく、影響を受けるすべてのページを各指摘の詳細とともに一覧表示します。
- `--json` — レポートを JSON として標準出力に出力します。
- `--codex` / `--claude` — 指摘を Codex または Claude Code に渡し、対話形式で修正させます。

## CI を失敗させる [#failing-ci]

基準になるのは終了コードです。デフォルトでは、`blume audit` はエラーがあるときだけ失敗します。エラーとは、ビルドされていないページへのリンク、リダイレクトループ、無効なサイトマップなど、確実に壊れているものです。改善を勧めるだけの指摘（短すぎる description、タイトルの重複など）は警告として扱われ、ビルドは失敗しません。

```bash
blume audit                      # fails on errors
blume audit --fail-on warning    # also fails on warnings
```

## 稼働中のデプロイを確認する [#checking-a-live-deployment]

実際のサーバーでしか確認できないこともあります。たとえば、`dist/` にあるページが誤ったリライトのせいで実際には 404 になっていないか、レスポンスが圧縮されているか、といった点です。HTML には問題がないのに、`X-Robots-Tag` ヘッダーのせいで気づかないうちにインデックスから外れていないか、[`redirects`](/docs/deployment#redirects) に記載した古い URL がそれぞれ設定どおりの場所へ実際にリダイレクトされるかも、サーバーでしか確認できません。これらのチェックを追加するには、監査の対象にデプロイを指定します。

```bash
blume audit --url https://docs.example.com
blume audit --url https://docs.example.com --external   # also probe outbound links
```

これらのリクエストは、クローラーとしてではなく、通常の HTTP クライアントとして送信されます。ホストのボット対策によって、クローラーになりすましたクライアントがブロックされることがあるため、監査では Googlebot や AI クローラーのユーザーエージェントを送信しません。そのため、クローラーを別扱いするファイアウォールや CDN のルールは検証されません。こうしたルールは、Google Search Console の URL 検査など、クローラー側が提供するツールで確認してください。

監査では、完全一致で指定したリダイレクトについて、すべての古い URL にリクエストを送ります（パターンで指定したリダイレクトは、リクエストすべき個別の URL が決まらないため対象外です）。404 を返したものはエラーになります。200 を返したものは警告になります。ビルドが書き出したリダイレクトファイルをホストが読み込んでいない場合、その URL では HTTP リダイレクトではなく、ビルドが生成した meta refresh のページが配信されます。読者はこのページから移動できますが、クローラーは移動しないことがあります。各ホストが読み込むファイルについては、[リダイレクト](/docs/deployment#redirects) を参照してください。

外部リンクは一律に失敗扱いにはせず、状況に応じて評価します。404 や 410、または名前解決できないホスト名は、修正できるリンク切れです。一方、それ以外のエラーステータス（ボットを拒否するサイトが返す 401 や 403、429、5xx）、接続の拒否、タイムアウトは、たいていレート制限か相手側の障害なので、警告として報告します。プレースホルダーのドメインやローカルサーバーなど、監査を実行する環境からは確認できない URL は、`--ignore` で対象から外してください。

## エージェントで指摘を修正する [#fixing-the-findings-with-an-agent]

[Codex](https://developers.openai.com/codex/cli) や [Claude Code](https://claude.com/claude-code) を使っている場合は、監査の指摘をそのまま渡せます。

```bash
blume audit --codex   # or --claude
```

このコマンドは完全な JSON レポートをファイルに書き出します。ターミナルに表示される 3 ページ分のプレビューではなく、影響を受けるすべてのページが含まれます。続いて、指摘を順に処理させるプロンプトとともにエージェントを対話モードで起動します。エージェントは、各指摘が示すソースファイルを編集して提案どおりに修正し、レポートがクリーンになるまで `blume build` と `blume audit` を再実行します。このセッションは意図的に対話型にしています。編集内容はエージェント自身の権限フローで確認できます。また、コンテンツを削除して指摘を解消しないよう、エージェントに指示しています。

`--only` と `--skip` は、レポートと同じように、エージェントに渡す内容も絞り込みます。そのため、1 カテゴリずつ渡すこともできます。

## チェックする項目としない項目 [#what-it-does-and-doesnt-check]

チェックの範囲は、汎用の SEO クローラーより意図的に狭くしています。汎用クローラーが報告する項目の多くは、Blume のサイトでは発生しません。Blume は `rel=nofollow` を出力しませんし、Vite のコンテンツハッシュ付きバンドルが欠けたりリダイレクトしたりすることもありません。こうした項目を毎回ゼロ件と報告しても、レポートを読み飛ばす習慣がつくだけです。

次の 3 つの制限は明記しておきます。

- **構造化データ** は、形式が正しいかどうか（有効な JSON であること、`@context` があること、すべてのノードに `@type` があること）だけを検証します。schema.org の語彙全体や Google のリッチリザルトのルールに照らした検証は行いません。
- **コントラスト** は、テーマ設定で指定した色を対象にチェックします。要素ごとにはチェックしません。監査ではページをレンダリングしないため、MDX や `theme.css` に手作業で記述した色は計測されません。
- **Core Web Vitals** はチェックしません。計測には実際のブラウザが必要です。実は何も計測しないフラグを用意するくらいなら、フラグがないほうがましです。そのため `blume audit` は、オフラインで確認 _できる_ レイアウトシフトの原因（`width`/`height` のない画像、サイズが大きすぎるアセット）だけを報告し、それ以外は現時点では対象外にしています。

監査で実行されなかったチェックは、合格扱いにはせず、スキップとして報告します。

```
⊘ network      skipped — pass --url <origin> (12 checks)
⊘ external     skipped — pass --external (2 checks)
```

## チェックカタログ [#check-catalog]

`blume audit` が報告できるすべてのチェックをカテゴリ別にまとめています。各チェックには、デフォルトの重大度、実行されるティア、レポートが提案する修正方法を記載しています。`--only` と `--skip` には、これらの ID（`BLUME_AUDIT_` プレフィックスは省略できます）またはカテゴリのキーを指定できます。キーはカテゴリの見出しと同じとは限らないため、次の表を参照してください。たとえば、`--only Internationalization` ではなく `blume audit --only i18n` と指定します。

| カテゴリ              | キー              |
| --------------------- | ----------------- |
| アクセシビリティ      | `accessibility`   |
| コンテンツ            | `content`         |
| 重複                  | `duplicates`      |
| インデックス登録      | `indexability`    |
| リンク                | `links`           |
| リダイレクト          | `redirects`       |
| ソーシャルカード      | `social`          |
| 国際化                | `i18n`            |
| アセット              | `assets`          |
| サイトマップ          | `sitemap`         |
| robots.txt            | `robots`          |
| AI からの見つけやすさ | `ai`              |
| 構造化データ          | `structured-data` |
| 稼働中のデプロイ      | `network`         |

### コンテンツ [#content]

#### title タグがない、または空 [#title-missing]

`BLUME_AUDIT_TITLE_MISSING` · error · ビルド済み HTML から

修正：ページのフロントマターに `title` を追加します。

#### title タグが複数ある [#title-multiple]

`BLUME_AUDIT_TITLE_MULTIPLE` · error · ビルド済み HTML から

修正：ページのレイアウトまたは MDX から余分な `<title>` を削除します。

#### タイトルが長すぎる、または短すぎる [#title-length]

`BLUME_AUDIT_TITLE_LENGTH` · warning · ビルド済み HTML から

修正：適切な長さに収まるよう、フロントマターの `title` を書き直します。

#### メタディスクリプションがない、または空 [#description-missing]

`BLUME_AUDIT_DESCRIPTION_MISSING` · warning · ビルド済み HTML から

修正：ページのフロントマターに `description` を追加します。

#### メタディスクリプションタグが複数ある [#description-multiple]

`BLUME_AUDIT_DESCRIPTION_MULTIPLE` · error · ビルド済み HTML から

修正：ページのレイアウトまたは MDX から、description 用の余分な `<meta>` を削除します。

#### メタディスクリプションが長すぎる、または短すぎる [#description-length]

`BLUME_AUDIT_DESCRIPTION_LENGTH` · warning · ビルド済み HTML から

修正：適切な長さに収まるよう、フロントマターの `description` を書き直します。

#### H1 タグがない、または空 [#h1-missing]

`BLUME_AUDIT_H1_MISSING` · warning · ビルド済み HTML から

修正：ページに `title` を設定します。Blume はこれをページの `<h1>` としてレンダリングします。

#### H1 タグが複数ある [#h1-multiple]

`BLUME_AUDIT_H1_MULTIPLE` · warning · ビルド済み HTML から

修正：本文中の余分な `# Heading` を `##` に下げます。Blume は `title` をすでに h1 としてレンダリングしています。

#### 単語数が少ない [#low-word-count]

`BLUME_AUDIT_LOW_WORD_COUNT` · info · ビルド済み HTML から

修正：ページの内容を増やすか、より大きなページに統合します。

#### 見出しレベルが飛んでいる（例：h2 から h4） [#heading-skip]

`BLUME_AUDIT_HEADING_SKIP` · info · ビルド済み HTML から

修正：見出しを 1 つ下のレベルに合わせます。レベルが飛んでいると、目次の入れ子構造やスクリーンリーダーのアウトラインが崩れます。

#### ページの日付が未来になっている [#future-dated-page]

`BLUME_AUDIT_FUTURE_DATED_PAGE` · info · ビルド済み HTML から

修正：`date` を修正するか、公開予定日までページを公開しないでおきます。

#### viewport が設定されていない [#viewport-missing]

`BLUME_AUDIT_VIEWPORT_MISSING` · error · ビルド済み HTML から

修正：eject したレイアウトに viewport の `<meta>` を戻します。

### 重複 [#duplicates]

#### タイトルの重複 [#duplicate-title]

`BLUME_AUDIT_DUPLICATE_TITLE` · warning · ビルド済み HTML から

修正：ページごとに異なる `title` を設定します。検索エンジンはこれを検索結果の見出しとして表示します。

#### メタディスクリプションの重複 [#duplicate-description]

`BLUME_AUDIT_DUPLICATE_DESCRIPTION` · warning · ビルド済み HTML から

修正：ページごとに異なる `description` を設定します。

#### canonical のない重複ページ [#duplicate-content]

`BLUME_AUDIT_DUPLICATE_CONTENT` · warning · ビルド済み HTML から

修正：ページを統合するか、1 ページを残してほかのすべてのページに `seo.canonical` を設定します。

### インデックス登録 [#indexability]

#### deployment.site が設定されていない [#site-not-set]

`BLUME_AUDIT_SITE_NOT_SET` · warning · ビルド済み HTML から

修正：blume.config.ts の `deployment.site` に、サイトの公開 URL を設定します。

#### deployment.site がデプロイ時に推定される [#site-inferred-at-deploy]

`BLUME_AUDIT_SITE_INFERRED_AT_DEPLOY` · info · ビルド済み HTML から

修正：本番環境に近いビルド（例：`VERCEL=1 VERCEL_PROJECT_PRODUCTION_URL=<host> blume build`）を監査するか、`--url <origin>` でデプロイそのものを監査します。`deployment.site` はハードコードしないでください。デプロイのたびにプラットフォームが設定します。

#### noindex のページで canonical を宣言している [#canonical-on-noindex]

`BLUME_AUDIT_CANONICAL_ON_NOINDEX` · warning · ビルド済み HTML から

修正：noindex のページから canonical を削除します。Google はこの組み合わせを矛盾とみなし、どちらか一方を無視することがあります。

#### 下書きページがビルドに含まれている [#draft-page-published]

`BLUME_AUDIT_DRAFT_PAGE_PUBLISHED` · warning · ビルド済み HTML から

修正：デプロイ前に `--preview` を付けずに再ビルドします。ページを公開する準備ができている場合は、`draft: true` を削除します。

#### canonical URL がない [#canonical-missing]

`BLUME_AUDIT_CANONICAL_MISSING` · warning · ビルド済み HTML から

修正：`deployment.site` を設定します。これにより、Blume が絶対 URL で canonical を出力できるようになります。

#### canonical でないページ [#canonical-not-self]

`BLUME_AUDIT_CANONICAL_NOT_SELF` · info · ビルド済み HTML から

修正：`seo.canonical` をこのページに向けるか、`seo.canonical` を削除して、デフォルトの自己参照 canonical を使います。

#### canonical がリンク切れのページ、またはリダイレクトするページを指している [#canonical-bad-target]

`BLUME_AUDIT_CANONICAL_BAD_TARGET` · error · ビルド済み HTML から

修正：`seo.canonical` を、実在してリダイレクトしないページに向けます。

#### canonical のプロトコルがサイトと一致しない [#canonical-protocol-mismatch]

`BLUME_AUDIT_CANONICAL_PROTOCOL_MISMATCH` · error · ビルド済み HTML から

修正：`seo.canonical` のプロトコルを `deployment.site` と揃えます。

#### ページがインデックス登録されない設定になっている [#robots-meta-unexpected]

`BLUME_AUDIT_ROBOTS_META_UNEXPECTED` · info · ビルド済み HTML から

修正：インデックスに登録すべきページであれば、フロントマターから `noindex` を削除します。

#### ページが Googlebot のクロール上限（2 MB）を超えている [#html-too-large]

`BLUME_AUDIT_HTML_TOO_LARGE` · error · ビルド済み HTML から

修正：ページを分割します。Googlebot は HTML ドキュメントを 2 MB までしか読み込みません。

#### X-Robots-Tag ヘッダーがページの robots メタタグと矛盾している [#robots-header-conflict]

`BLUME_AUDIT_ROBOTS_HEADER_CONFLICT` · error · `--url` が必要

修正：X-Robots-Tag ヘッダーを削除するか、ページの robots メタタグと内容を揃えます。

### リンク [#links]

#### リンク切れのページへのリンクがある [#link-to-broken]

`BLUME_AUDIT_LINK_TO_BROKEN` · error · ビルド済み HTML から

修正：リンク先を修正するか、リンク先のページを作成します。

[`deployment.base`](/docs/deployment#subpath-deploys) を設定している場合、base を含まないルート相対リンクもここで報告されます。そのパスでは、ホストがこのビルドの内容を何も配信しないためです。一方、同じホスト上で base の外を指す完全な URL は報告されません。これは、ホストがドキュメントと並べて配信している別のアプリにページからリンクするときの書き方だからです。

#### リダイレクトへのリンクがある [#link-to-redirect]

`BLUME_AUDIT_LINK_TO_REDIRECT` · warning · ビルド済み HTML から

修正：リダイレクトを経由せず、最終的なリンク先に直接リンクします。

#### 孤立ページ（ナビゲーションからしかたどり着けない） [#orphan-page]

`BLUME_AUDIT_ORPHAN_PAGE` · warning · ビルド済み HTML から

修正：関連するページの本文から、このページにリンクします。

#### 内部リンクにサイト自身のオリジンがハードコードされている [#internal-link-absolute]

`BLUME_AUDIT_INTERNAL_LINK_ABSOLUTE` · warning · ビルド済み HTML から

修正：ルート相対パス（`/docs/x`）を使います。こうすると、プレビュー環境や `basePath` を設定した場合でもリンクが切れません。

#### nofollow の付いた内部リンクがある [#internal-link-nofollow]

`BLUME_AUDIT_INTERNAL_LINK_NOFOLLOW` · info · ビルド済み HTML から

修正：`rel="nofollow"` を削除します。これがあると、このページからサイト内の他のページへ評価が渡らなくなります。

#### URL にスラッシュが二重に含まれている [#double-slash-url]

`BLUME_AUDIT_DOUBLE_SLASH_URL` · error · ビルド済み HTML から

修正：`basePath` / `deployment.base` を確認します。値の末尾にスラッシュがあると `//` になります。

#### リンクのフラグメントがリンク先ページのどの id とも一致しない [#anchor-broken]

`BLUME_AUDIT_ANCHOR_BROKEN` · warning · ビルド済み HTML から

修正：フラグメントをリンク先ページに実在する見出しに向けるか、本来指すはずだった見出しを修正します。

#### URL に大文字、アンダースコア、またはスペースが含まれている [#url-style]

`BLUME_AUDIT_URL_STYLE` · info · ビルド済み HTML から

修正：ソースファイル名を、小文字でハイフン区切りのスラッグに変更します。すでに公開済みの場合は、古い URL からのリダイレクトも追加します。

### リダイレクト [#redirects]

#### 壊れたリダイレクト [#redirect-broken]

`BLUME_AUDIT_REDIRECT_BROKEN` · error · ビルド済み HTML から

修正：リダイレクト先を実在するページにします。

#### リダイレクトループ [#redirect-loop]

`BLUME_AUDIT_REDIRECT_LOOP` · error · ビルド済み HTML から

修正：`redirects` 内の循環を解消します。このままではリダイレクトがどこにも到達しません。

#### リダイレクトチェーン [#redirect-chain]

`BLUME_AUDIT_REDIRECT_CHAIN` · warning · ビルド済み HTML から

修正：途中のリダイレクトをすべて、最終的なリンク先に直接向けます。

### アクセシビリティ [#accessibility]

これらのチェックは、各ページではなくテーマ設定に対して実行されます。テーマカラーはサイト全体で 1 つだけ選ぶものだからです。このチェックはビルドと同じ方法で色を解決し（モードごとのプリセットのシェード、塗りつぶしの上に表示される白または濃い色のラベル）、テーマが描画するすべてのテキストの色を、ライトモードとダークモードの両方で、本文テキスト向けの WCAG AA のコントラスト比 4.5:1 と照らし合わせて計測します。

#### テーマカラーが WCAG AA のコントラスト基準を満たしていない [#theme-contrast-low]

`BLUME_AUDIT_THEME_CONTRAST_LOW` · warning · テーマ設定から

修正：`theme.accent: { light, dark }` を使ってモードごとに、ライトモードにはより濃いシェードを、ダークモードにはより明るいシェードを選びます。

チェック対象は、ページ上のアクセントカラーのテキスト、アクセントカラーと `action` の塗りつぶしの上に表示されるラベル、カスタムの `background` の上に表示される本文テキストと補助テキストです。各指摘には、色の組み合わせ、モード、コントラスト比が示されます。

#### テーマカラーのコントラストをチェックできない [#theme-color-unchecked]

`BLUME_AUDIT_THEME_COLOR_UNCHECKED` · info · テーマ設定から

修正：コントラストをチェックできるよう、色を hex、`rgb()`、`hsl()`、`hwb()`、`lab()`、`lch()`、`oklab()`、`oklch()`、または色名で記述します。

#### noindex のページがサイトマップにある [#noindex-in-sitemap]

`BLUME_AUDIT_NOINDEX_IN_SITEMAP` · error · ビルド済み HTML から

`BLUME_AUDIT_SITEMAP_BAD_URL` · error · ビルド済み HTML から

`BLUME_AUDIT_SITEMAP_OUT_OF_SCOPE` · warning · ビルド済み HTML から

### robots.txt

#### robots.txt がない [#robots-missing]

`BLUME_AUDIT_ROBOTS_MISSING` · warning · ビルド済み HTML から

#### robots.txt に構文エラーがある [#robots-invalid]

`BLUME_AUDIT_ROBOTS_INVALID` · error · ビルド済み HTML から

修正：robots.txt の各行は、`Field: value` 形式のディレクティブかコメントでなければなりません。

#### robots.txt がサイトマップに載っているページを disallow している [#robots-disallows-indexable]

`BLUME_AUDIT_ROBOTS_DISALLOWS_INDEXABLE` · error · ビルド済み HTML から

#### robots.txt が特定のクローラーに対してサイトマップ内のページをブロックしている [#robots-blocks-crawler]

`BLUME_AUDIT_ROBOTS_BLOCKS_CRAWLER` · warning · ビルド済み HTML から

修正：そのクローラーにこれらのページを読み込ませたい場合は、そのクローラーの `User-agent` グループにあるルールの範囲を狭めるか、ルールを削除します。AI クローラーを意図的にブロックしているのであれば問題ありません。このチェックをスキップしてください。

専用の `User-agent` グループで指定されたクローラーは、そのグループのルールだけに従います。そのため、そのグループにルール（`User-agent: GPTBot` の後に `Disallow: /`）があると、ほかのクローラーはページを読み込めても、そのクローラーだけが締め出されます。監査では、各クローラーについて、最初のページをブロックしているルールの位置で 1 回だけ報告します。

`BLUME_AUDIT_ROBOTS_SITEMAP_MISSING` · info · ビルド済み HTML から

修正：`deployment.site` を設定します。これにより、robots.txt でサイトマップを参照できるようになります。

#### robots.txt にアクセスできない [#robots-not-accessible]

修正：robots.txt をサイトのルートに配置し、アクセスできるようにします。

### AI からの見つけやすさ [#ai-discoverability]

#### llms.txt がビルドに含まれていない [#llms-txt-missing]

`BLUME_AUDIT_LLMS_TXT_MISSING` · warning · ビルド済み HTML から

#### llms.txt に、ビルドで配信されないページが載っている [#llms-txt-stale-entry]

`BLUME_AUDIT_LLMS_TXT_STALE_ENTRY` · warning · ビルド済み HTML から

`BLUME_AUDIT_LLMS_TXT_PAGE_MISSING` · warning · ビルド済み HTML から

#### DNS-AID のエージェント検出用レコードがない [#dns-aid-missing]

`BLUME_AUDIT_DNS_AID_MISSING` · info · `--url` が必要

#### DNS-AID レコードが DNSSEC で認証されていない [#dns-aid-unsigned]

`BLUME_AUDIT_DNS_AID_UNSIGNED` · info · `--url` が必要

修正：ゾーンで DNSSEC を有効にします。これにより、検証を行うリゾルバーが認証済みの DNS-AID 応答を返せるようになります。DNS プロバイダーが DNSSEC に対応していなくても、レコードは署名なしで動作します。
