---
title: 国際化
description: ロケール対応ルーティング、言語ごとのナビゲーション、翻訳された UI、SEO を備え、複数の言語でドキュメントを配信します — すべて規約優先で。
---

Blume は 1 つのプロジェクトを多言語で配信します。翻訳したファイルを適切な場所に置くだけで、Blume がルーティング、言語スイッチャー、ロケールごとのナビゲーション、SEO を自動的に構成します — 別途メンテナンスするルーティング層はありません。オプトイン方式なので、`i18n` ブロックがなければサイトはこれまでどおり単一言語のままです。

## 有効にする

ロケールの一覧と、どれをデフォルトにするかを記載した `i18n` ブロックを追加します:

```ts blume.config.ts lineNumbers
i18n: {
  defaultLocale: "en",
  locales: [
    { code: "en", label: "English" },
    { code: "fr", label: "Français" },
    { code: "ar", label: "العربية", dir: "rtl" },
  ],
}
```

各ロケールには `code`(URL で使用)、`label`(言語スイッチャーに表示)、および右から左に書く文字体系のための任意の `dir`(デフォルトは `"ltr"`)があります。

## 翻訳コンテンツを整理する

デフォルトロケールはコンテンツのルートに置きます。それ以外のロケールは、その `code` を名前とするトップレベルのフォルダーとして、デフォルトの構造をミラーリングします:

```txt
docs/
  index.mdx               ->  /
  guides/quickstart.mdx   ->  /guides/quickstart
  fr/
    index.mdx             ->  /fr
    guides/quickstart.mdx ->  /fr/guides/quickstart
  ar/
    index.mdx             ->  /ar
```

| ファイル                        | ルート                  |
| ------------------------------- | ----------------------- |
| `docs/index.mdx`                | `/`                     |
| `docs/guides/quickstart.mdx`    | `/guides/quickstart`    |
| `docs/fr/guides/quickstart.mdx` | `/fr/guides/quickstart` |

翻訳したいファイルだけを翻訳すれば済みます — それ以外はすべて自動的にフォールバックします([フォールバック](#fallbacks)を参照)。

### ファイル名のサフィックス

翻訳を元のファイルの隣に置いておきたい場合は、`parser: "dot"` を設定し、フォルダーを使う代わりにロケールのサフィックスを付けてファイル名を付けます:

```txt
docs/
  guides/quickstart.mdx     ->  /guides/quickstart      (default)
  guides/quickstart.fr.mdx  ->  /fr/guides/quickstart   (French)
```

翻訳がまばらな場合に適しています — ツリー全体をミラーリングすることなく、翻訳済みの少数のページだけを同じ場所に配置できます。

### 共有ファイル

変更履歴やステータスページなど、すべての言語で内容が同じコンテンツには `$` マーカーを付けると、1 つのファイルが重複なくすべてのロケールに対応します:

```txt
docs/changelog.$.mdx   ->  /changelog and /fr/changelog (same content)
docs/guides/meta.$.ts   (folder meta applied to every locale)
```

ロケール固有の `meta.ts` があれば、その言語については共有のものを引き続き上書きします。

## デフォルトロケールの URL

デフォルトでは、デフォルトロケールには URL プレフィックスが付かず(`/`、`/guides/quickstart`)、他のロケールにはプレフィックスが付きます(`/fr/…`)。これにより主要言語の URL がすっきりします。デフォルトを含むすべてのロケールにプレフィックスを付けるには:

```ts blume.config.ts lineNumbers
i18n: {
  // …
  hideDefaultLocalePrefix: false, // /en/…, /fr/…
}
```

## ロケールごとのナビゲーション

各言語には、そのロケールのファイルから構築された独自のサイドバーが用意されます — したがって翻訳は構造、順序、ラベルの点で分岐できます。フォルダーの [`meta.ts`](/docs/content/meta) ファイルもロケールごとに解決されます: デフォルトの `dir` パーサーでは、`fr/guides/` の下に `meta.ts` を置けばフランス語グループを独立して並べ替えられます。`dot` パーサーでは翻訳が元のファイルの隣に置かれるため、フォルダーの `meta.ts` はすべてのロケールに適用されます。[ナビゲーション](/docs/content/navigation)に関するそれ以外の点は、言語ごとに同じように機能します。

## フォールバック

ページがまだ翻訳されていない場合、Blume はローカライズされた URL でフォールバックロケールのコンテンツをレンダリングします — そのためリンクは機能し、ページは完全に事前レンダリングされ、検索エンジンが行き止まりに送られることもありません。フォールバックのデフォルトは `defaultLocale` です:

```ts blume.config.ts lineNumbers
i18n: {
  // …
  fallbackLocale: "en", // default; set to null to 404 instead
}
```

フォールバックページは検索インデックスから除外され、`hreflang` でも実際の翻訳としては提示されないため、未翻訳のコンテンツがランキングを奪い合うことはありません。それでもそのロケールのサイドバーには表示されるので、ナビゲーションは完全なまま保たれます — 読者はどの言語でもすべてのページに到達できます。

:::tip
最も重要なページ — ホームページ、クイックスタート、主要なガイド — から翻訳を始め、残りはフォールバックさせましょう。リンクを壊すことなく、時間をかけて翻訳を埋めていけます。
:::

## エージェントによる翻訳

ロケールを手作業で埋める必要はありません。[`blume translate`](/docs/reference/translate) は、各ロケールで欠落しているか古くなっているページをすべて見つけ出し、ローカルのエージェント CLI([Claude Code](https://claude.com/claude-code) または [Codex](https://developers.openai.com/codex/cli))で翻訳します:

```bash
blume translate --claude
```

Blume は各結果の構造 — フロントマター、コードフェンス、リンク — を検証し、ファイル自体を書き込みます。エージェントはテキストを翻訳するだけです。コミットされる台帳(`blume.translations.json`)が、各翻訳がどのソースリビジョンに由来するかを記録するため、再実行では変更があったものだけが対象になり、手作業で書いた翻訳はそのまま採用され、上書きされることはありません。CI では、ソースページが翻訳より先に進んでいる場合に `blume translate --check` が失敗します。

## 言語スイッチャー

i18n が有効になると、`locales` から生成された言語スイッチャーがヘッダーに自動的に表示されます。各ページについて、すべての言語の対応する翻訳へリンクします。翻訳が存在しない場合はフォールバックページにリンクし、未翻訳であることを示します。設定は不要です。

## 翻訳された UI

Blume は自身のインターフェイス周りの要素 — 「このページの内容」、「検索」、「GitHub で編集」など — の翻訳を組み込みで同梱しているため、組み込みパックがあるロケールでは最初から UI が翻訳された状態になります。**翻訳するのはコンテンツだけです。**

パックは 30 を超える言語 — アラビア語、ベンガル語、ブルガリア語、カタルーニャ語、中国語(簡体字と繁体字)、クロアチア語、チェコ語、デンマーク語、オランダ語、フィンランド語、フランス語、ドイツ語、ギリシャ語、ヘブライ語、ヒンディー語、ハンガリー語、インドネシア語、イタリア語、日本語、韓国語、ノルウェー語、ペルシア語、ポーランド語、ポルトガル語(およびブラジルポルトガル語)、ルーマニア語、ロシア語、セルビア語、スロバキア語、スペイン語、スウェーデン語、タイ語、トルコ語、ウクライナ語、ベトナム語 — で提供されています。これらはコミュニティによってメンテナンスされています — ロケールを追加したり翻訳を改善したりするには PR を開いてください。

欠落している文字列や同梱されていない文字列は、デフォルトロケールに、次いで英語にフォールバックします。文字列を上書きしたり独自の言語を提供したりするには、ロケールをキーとして `i18n.ui` を設定します:

```ts blume.config.ts lineNumbers
i18n: {
  // …
  ui: {
    fr: {
      search: { button: "Rechercher", placeholder: "Rechercher…" },
      page: { previous: "Précédent", next: "Suivant" },
    },
  },
}
```

## SEO

ローカライズされた SEO は自動的に処理されます — ページごとにメタデータを書く必要はありません:

- `<html lang>` と `dir` はアクティブなロケールから設定されます。
- `hreflang` の alternate は、ページの実在するすべての翻訳に加えて、デフォルトロケールを指す `x-default` にリンクします。
- 正規 URL はロケールに応じて正しく設定され、JSON-LD には `inLanguage` が含まれます。

これらを絶対 URL として出力できるように、[`deployment.site`](/docs/deployment) を設定してください。

## 検索

検索はアクティブな言語にスコープされます: `/fr/…` のページではダイアログがフランス語の結果を返し、**すべての言語** トグルですべてのロケールを一度に横断検索できます。デフォルト(Orama)と FlexSearch のインデックスはブラウザー内でフィルタリングします。ホスト型プロバイダーは各レコードに `locale` ファセットを持たせます。

## 右から左

ロケールに `dir: "rtl"` を設定すると、Blume はインターフェイス全体 — サイドバー、ヘッダー、目次、ページネーション、検索、メニュー — をミラーリングし、`<html dir>` もそれに合わせて設定します。意図的に左から右のままにしているものが 2 つあります: **コードブロック**(コードはどの言語でも LTR で読みます)と **フォールバックコンテンツ** — 未翻訳のページは実際に書かれている言語の方向を保つため、RTL ロケールの下で表示される英語も正しく読める一方で、周囲の要素はミラーリングされます。
