[i18n](/docs/content/i18n) を有効にすると、ソースページを編集するたびに、その翻訳が知らないうちに古くなっていきます。`blume translate` はこのループを閉じます。各ロケールでどのページが不足または古くなっているかを正確に算出し、ローカルのエージェント CLI でヘッドレスに翻訳し、実行内容をコミット対象の台帳に記録するので、次回の実行と CI が最新状態を把握できます。

```bash
blume translate --claude
```

```
blume translate  3 item(s) · 2 locale(s) · Claude Code

  ✔ docs/guides/install.mdx → fr 24.2s $0.11
  ✔ docs/guides/install.mdx → de 22.8s $0.10
  ✔ meta titles (2) → de 4.1s $0.01

  Translated 3 files into 2 locales · 1 adopted · 14 already up to date · 51.1s · $0.22
```

## 仕組み

パイプラインは Blume が管理し、エージェントはテキストの翻訳だけを行います。作業が必要な各ファイルについて、Blume は翻訳プロンプトを組み立て、ファイル・シェル・Web の各ツールを無効にした状態でエージェント CLI をヘッドレスに実行し、応答の構造を検証したうえで、対象ファイルを自ら書き込みます。`--claude` では [Claude Code](https://claude.com/claude-code)、`--codex` では [Codex](https://developers.openai.com/codex/cli) を使います。Blume は API キーを保持せず、モデルを自ら呼び出すこともありません。

検証を通過した書き込みはすべて、プロジェクトルートの `blume.translations.json` に記録されます。ソースファイルとロケールの組み合わせごとに、翻訳した時点のソースのハッシュを保存します。**このファイルはコミットしてください。** これによって、再実行時に「すでに翻訳済み」と「翻訳済みだがその後ソースが変更された」を区別でき、CI ゲートも実現できます。

台帳はファイルが 1 件終わるたびにフラッシュされるため、長い実行を中断しても（Ctrl+C）失われるのは処理中だった翻訳だけで、次回の実行は中断地点から再開します。ファイルはデフォルトで 4 件ずつ並行処理されます。マシン性能とエージェントのレート制限が許すなら `--concurrency` で増やしてください。

再実行は差分ベースです。前回の翻訳以降に変更のないソースはスキップされるため、1 ページを編集したあとに `blume translate` を実行すると、ロケールごとに 1 ページだけが翻訳されます。

## 翻訳される対象

- **ページ** — デフォルトロケールの `.md`/`.mdx` ファイル。エージェントは本文と、人間が目にするフロントマターの値（`title`、`description`、`sidebar.label`、`sidebar.badge`、`seo.title`、`seo.description`）のみを翻訳します。出力先はパーサーに従います。`dir` では `fr/guides/install.mdx`、`dot` では `guides/install.fr.mdx` です。
- **フォルダーのナビゲーションタイトル** — `dir` パーサーでは、各ロケールに必要な [`meta.ts`](/docs/content/meta) のタイトルが 1 回のバッチ呼び出しで翻訳されます。生成されるロケールごとの `meta.ts` は、その他のキー（`order`、`pages`、`icon`、`collapsed`）をそのままコピーするため、ロケールのサイドバーは並び順を保ちます。

手作業で書いた翻訳は**取り込まれ、上書きされることはありません**。翻訳が存在するのに台帳エントリがない場合は、最新として記録され、そのまま残されます。再翻訳するのは `--force` のときだけです。

## 検証

構造についてエージェントは一切信頼されません。書き込む前に、Blume は各応答を検査し、ソースからファイルを再構築します。

- フロントマターはソースファイルのデータから再構築され、翻訳可能な 6 つの値だけが上書きされます。エージェントが勝手に追加したキーは削除され、削除したキーは復元され、`slug`、`icon`、`order`、日付は仕組み上つねにソースそのままです。
- コードフェンスの数はソースと一致していなければならず、本文は空であってはならず、フロントマターはパースできなければなりません。

検証に失敗した応答は何も書き込みません。その項目は失敗として報告され、実行は次へ進みます。成功したものはすべて台帳に記録されたままなので、再実行では失敗分だけが再試行されます。

## CI を失敗させる

`blume translate --check` は読み取り専用のゲートです。不足および古くなっているすべての組み合わせを報告し、ずれがあれば非ゼロで終了します。エージェントの実行も書き込みも行いません。

```bash
blume translate --check           # exit 1 when translations are missing or stale
blume translate --check --json    # machine-readable drift report on stdout
```

```yaml .github/workflows/translations.yml
- run: npx blume translate --check
```

JSON レポートは `blume validate --json`、`blume audit --json`、`blume eval --json` と同じ `diagnostics` + `summary` の形式を持ち、ずれはロケールごとにグループ化されます。手作業で書かれた（未追跡の）翻訳がゲートを失敗させることはありません。

## 制限事項

- メタタイトルの翻訳は `dir` パーサー専用です。`dot` パーサーにはロケールごとの `meta.ts` の仕組みがありません。関数をデフォルトエクスポートしている `meta.ts` は警告とともにスキップされるので、そのロケールの分は手作業で書いてください。
- リモートおよび CMS を参照元とするソースはスキップされます。翻訳を書き込むローカルファイルが存在しないためです。
- 翻訳の品質はエージェント次第です。他のコントリビューションと同じようにレビューしてください。台帳が保証するのは鮮度だけで、流暢さではありません。

## フラグ

- `--claude` / `--codex` — 翻訳に使うエージェント CLI。いずれか 1 つが必須です（`--check` の場合を除く）。
- `--check` — ずれを報告して非ゼロで終了します。何も書き込みません。
- `--concurrency <n>` — 並行して動かすエージェントセッション数。デフォルトは `4`、最大は `16` です。
- `--locale <codes>` — 対象ロケールのカンマ区切り指定（デフォルトはデフォルト以外のすべてのロケール）。
- `--force` — 最新のファイルや手作業で書いたファイルも含め、すべてを再翻訳します。
- `--timeout <seconds>` — ファイルごとのエージェントの制限時間。デフォルトは `600` です。この上限はハングしたエージェントを捕捉するためのもので、大きなページでも十分に完了できる余裕があります。
- `--json` — どちらのモードでも、レポートを JSON として標準出力に出力します。
