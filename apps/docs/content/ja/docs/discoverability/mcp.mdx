[Model Context Protocol](https://modelcontextprotocol.io) サーバーをホストすると、コーディングエージェント（Claude Code、Cursor、VS Code、claude.ai コネクター）がスクレイピングなしでドキュメントを直接検索・読み取りできるようになります。これはオプトイン方式です。

```ts blume.config.ts lineNumbers
agents: {
  mcp: {
    enabled: true,
    route: "/mcp", // where the server is mounted
  },
}
```

| オプション | デフォルト | 説明 |
| --- | --- | --- |
| `enabled` | `false` | MCP サーバーを生成してホストします。 |
| `route` | `/mcp` | Streamable-HTTP エンドポイントをマウントするパスです。 |
| `name` | title | クライアントに表示されるサーバー名（デフォルトは title）です。 |
| `instructions` | — | 接続するエージェントに渡される任意のシステムヒントです。 |

コンテンツページまたはカスタムページがすでにそのルートを使用している場合、サーバーは生成されません。ビルド時に警告が表示され、`llms.txt` やその他の [ディスカバリードキュメント](/docs/discoverability/agent-discovery) にもサーバーは含まれません。

## ツールとリソース [#tools-and-resources]

サーバーは読み取り専用のツール（`search_docs`、`get_page`、`list_pages`、`get_navigation`）と、すべてのページを MCP リソースとして公開します（`resources/list` は、`list_pages` と同様に未翻訳ページの i18n フォールバックコピーを除いて、各ページを配信 URL 上で `text/markdown` タイプとして列挙し、`resources/read` はそのページの [エージェント向け Markdown](/docs/discoverability/markdown)（`get_page` と同じ出力）を返します）。そのため、URI でコンテキストを添付するクライアントは、ツールを呼び出さずにドキュメントを閲覧できます。また、ディスカバリードキュメントを `/.well-known/mcp.json` と `/.well-known/mcp/server-card.json` で公開します。サーバーカードは [SEP-2127](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2127) Server Card 拡張スキーマ（逆 DNS 形式の `name`、`remotes` トランスポートエンドポイント）に準拠しており、提案の以前のリビジョンに対して構築されたスキャナー向けに initialize 形式の互換フィールド（`serverInfo`、`capabilities`、`transports`）も備えています。各ページの **Connect to MCP** メニューでは、Claude Code、Cursor、VS Code、Codex 向けのコピー＆実行式インストールを提供しています（[`deployment.site`](/docs/deployment) が設定されている場合に表示されます）。

`search_docs` は独自の全文検索インデックスを実行するため、[search](/docs/configuration/search) プロバイダーに関係なく動作します — `search: false` の場合でも同様です。MCP サーバーはページ内検索とは別の機能です。

[非表示ページ](/docs/content/navigation#hidden-pages) は、サイト内検索や `llms.txt` から除外されるのと同様に、`list_pages` と `resources/list` から除外され、[`search.indexing.includeHiddenPages`](/docs/configuration/search#excluding-pages) が有効でない限り `search_docs` からも除外されます。ただし、`get_page` と `resources/read` はルートを指定すれば非表示ページも返します。非表示は非公開という意味ではなく、ページは引き続きその URL で、また Markdown としても配信されます。

MCP に対応していないフレームワーク向けに、同じツールが [JSON API](/docs/discoverability/json-api) としてプレーンな HTTP 経由でも利用できます。

エンドポイントはリクエストボディを 64 KB までしか読み取らず、それより大きいリクエストには `413` を返します。存在しないツールの呼び出しや、`arguments` がオブジェクトではない呼び出しには、JSON-RPC の Invalid params エラー（`-32602`）が返されます。

## コンテンツタイプとファセットによるスコープ設定 [#scoping-by-content-type-and-facets]

`search_docs` と `list_pages` はどちらも任意の `contentTypes` フィルターを受け取り、指定したフロントマターの [`type`](/docs/content/frontmatter)（`["rfc"]`、`["blog", "changelog"]` など）のページに結果を絞り込みます。そのため、ドキュメントと RFC、ランブック、ポリシーが混在するサイトを扱うエージェントは、必要な種類のページに取得範囲を限定できます。すべての結果はそのコンテンツタイプを示し、`list_pages` の出力では使用中のタイプが表示されます。

どちらのツールも、サイトがコンテンツタイプごとに宣言するファセット（[`content.types.<type>.facets`](/docs/configuration#frontmatter)）— 値がフィルター可能なメタデータになるカスタムフロントマターキー — と照合する `filters` オブジェクトも受け取ります。

```json
{
  "query": "OpenAPI request schemas",
  "contentTypes": ["rfc"],
  "filters": { "domain": "architecture", "status": "enforced" }
}
```

`filters` のすべてのエントリが一致する必要があります（結果にはそのファセット値が含まれ、`list_pages` は各ページの値を表示します）。そのため、ナレッジベースは独自のサーバーを一切用意せずに、段階的開示型のエージェントワークフロー（適用済みの標準を列挙し、その中だけを検索する）を実現できます。

値は `list_pages` に表示されるとおりに、大文字と小文字の区別も含めて完全一致で照合されます。たとえば `"enforced"` は、`status` が `Enforced` のページには一致しません。ファセット値は文字列であるため、`filters` 内の数値や真偽値はその文字列表現と照合されます（`{"priority": 1}` は `priority: 1` のページに一致します）。また、リストなどそれ以外の形式の値は、フィルターとして使われずに無視されます。

## サーバー出力が必要です [#server-output-required]

MCP サーバーはライブエンドポイント（`/mcp`）であるため、静的ビルドでは実行できません。`blume/deploy` からホストアダプターを指定して、サーバー出力に切り替えてください。

```ts blume.config.ts lineNumbers
import { node } from "blume/deploy"; // or vercel, netlify, cloudflare

export default defineConfig({
  deployment: node({ site: "https://docs.example.com" }),
});
```

`agents.mcp.enabled` を有効にした静的ビルドは、ホストアダプターを設定するよう促すメッセージとともに即座に失敗します。アダプターについては [デプロイ](/docs/deployment) を参照してください。デプロイ後は、次のコマンドで Claude Code から接続できます。

```bash
claude mcp add --transport http my-docs https://docs.example.com/mcp
```
