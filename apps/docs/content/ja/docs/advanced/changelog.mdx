Blume には変更履歴が標準で用意されています。各リリースを通常のコンテンツファイルとして書き、`type: changelog` を指定するだけで、Blume がすべてのエントリを収集して生成されたインデックスページと RSS フィードにまとめます — レイアウトを構築する必要も、リストを管理する必要もありません。あるいはファイルを一切用意せず、[GitHub Releases から変更履歴を取得](#from-github-releases)することもできます。

## エントリを書く [#write-an-entry]

変更履歴のエントリは、フロントマターに `type: changelog` を持つ通常の `.md` または `.mdx` ページです。慣例として `changelog/` 配下に配置しますが、重要なのはフォルダではなく型です:

```mdx changelog/v1-2-0.mdx lineNumbers
---
title: v1.2.0
type: changelog
date: 2026-06-20
changelog:
  version: 1.2.0
  category: Features
---

A big batch of components landed this release — columns, frames, trees, and tooltips, plus code groups that render as proper language tabs.

- New `Accordion`, `Expandable`, and `Tooltip` components
- `CodeGroup` tabs with flush code blocks
```

インデックスとフィードが新しい順に並ぶよう、すべてのエントリに `date` を指定してください。クォートなしの YAML 日付でも問題ありません — Blume が正規化します。

### `changelog` オブジェクト [#the-changelog-object]

任意の `changelog` オブジェクトは、インデックスとフィードにより豊富なメタデータを追加します:

<TypeTable
  type={{
    "changelog.version": {
      type: "string",
      description:
        "リリースバージョン。タイトルがない場合は v 接頭辞付きのラベルにフォールバックします。",
    },
    "changelog.category": {
      type: "string",
      description:
        "エントリの横にタグとして表示されます。例: Release、Features、Fixes。",
    },
    "changelog.date": {
      type: "string",
      description:
        "公開日。ここに置いてもトップレベルに置いても構いません — どちらもインデックスと RSS フィードに反映されます。",
    },
  }}
/>

## インデックスページ [#the-index-page]

`type: changelog` のエントリが 1 つでもあれば、Blume は **`/changelog`** ページを自動的に生成します。サイドバーや目次のない、集中しやすい全幅のインデックスで、すべてのリリースを 1 行ずつ、新しい順かつ年ごとにグループ化して一覧表示します。そのため長い履歴も短いページに収まります（エージェントが 1 つのコンテキストウィンドウで読み取れるサイズを大きく下回ります）:

- エントリの**タイトル**が行のラベルになります — タイトルがない場合は `v{version}` です。そのエントリ自身のページへリンクしており、リリースノートはそこで全文がレンダリングされます。
- `category` はタイトルの隣にタグとしてレンダリングされるため、読者はリリースとプレリリース、あるいは機能追加と修正を一目で区別できます。
- 日付は設定された [`dateFormat`](/docs/configuration#date-format) に従いますが、行のグループですでに表示されている年は省略されます。
- 下書きと `sidebar.hidden` のエントリはスキップされます。

このページの見出しは **Changelog**（英語）で、その下に 1 行の説明が表示されます。設定ファイルの `changelog` で独自のものを指定できます。これらはページの `<title>`、メタディスクリプション、OG カード、そして `/changelog.md` にある Markdown ミラーの冒頭にも使われます:

```ts blume.config.ts
changelog: {
  title: "Release notes",
  description: "Every Acme SDK release, newest first.",
},
```

どちらも、[ヘッダータブのラベル](/docs/content/i18n#per-locale-navigation)と同様に、ロケールコードからテキストへのマップも受け付けます。インデックスはデフォルトのロケールでレンダリングされるため、そのロケールのエントリが表示されます。どちらかを未設定のままにすると組み込みのテキストが維持され、それは [UI 文字列のオーバーライド](/docs/content/i18n#translated-ui)（`i18n.ui` 配下の `changelog.title` と `changelog.description`）で置き換えられます。

このページは `/changelog` ルートが他に占有されていない場合にのみ表示されます。独自のデザインに置き換えるには、`pages/changelog.astro` に[カスタムページ](/docs/advanced/custom-pages)を追加してください — それが優先され、Blume はデフォルトのインデックスの生成を停止します。以前のタイムラインの構築に使われていた `<Update>` コンポーネントは、リリースノートをインラインで表示したいカスタムページ向けに引き続き提供されています。これは MDX コンポーネントには含まれていないため、`.astro` ページ自体でインポートしてください: `import Update from "blume/components/content/Update.astro";`。

`/changelog` を指すヘッダーの[タブ](/docs/content/navigation#tabs)はこのインデックスを開きます — `href` は不要です。

## GitHub Releases から [#from-github-releases]

エントリを手作業で書く代わりに、組み込みの [`githubReleases()` ソース](/docs/content/sources/github-releases)をリポジトリに向ければ、すべてのリリースが `type: changelog` エントリになります — 同じタイムラインとフィードが、すでに公開しているリリースから直接供給されます。Blume 自身の[変更履歴](/changelog)もこの方法で構築されています:

```ts blume.config.ts
import { filesystem, githubReleases } from "blume/sources";

content: {
  sources: [
    filesystem({ root: "content" }),
    githubReleases({
      prefix: "changelog",
      owner: "acme",
      repo: "sdk",
    }),
  ],
}
```

リリース名がタイトルになり、そのタグが `changelog.version` になり、公開日でタイムラインがソートされます。各リリースページには、そのノートから要約された固有のメタディスクリプションも付与されます — マークダウンを除去し、セクション見出しと changeset のコミットハッシュ接頭辞を削除し、[`blume audit`](/docs/cli/audit) がチェックする検索スニペットの長さに切り詰めたもので、サイトの説明にフォールバックすることはありません。プライベートリポジトリは `GITHUB_TOKEN` 環境変数で認証します。すべてのオプションについては[GitHub Releases](/docs/content/sources/github-releases)を参照してください。

## RSS フィード [#the-rss-feed]

Blume は **`/changelog/rss.xml`** に変更履歴フィードも構築し、`date` の新しい順にソートします。フィードには絶対的なサイト URL が必要なので、[`deployment.site`](/docs/deployment) を設定してください。その後 Blume がすべてのページに `<link rel="alternate">` タグを挿入し、読者が自動的に見つけられるようにします。

フィードはデフォルトで有効です。[`seo.rss`](/docs/discoverability/rss) で調整できます:

```ts blume.config.ts lineNumbers
seo: {
  rss: {
    enabled: true,
    types: ["blog", "changelog"],
    limit: 50,
  },
}
```

タイムラインを維持したままフィードだけをスキップするには、`rss.types` から `"changelog"` を削除してください。

## 構造化データ [#structured-data]

[構造化データ](/docs/discoverability/structured-data)が有効な場合、各変更履歴エントリは説明と公開日を伴う schema.org の **`TechArticle`** として出力されるため、検索エンジンがリリースを日付付きの記事としてインデックスできます。
