Blume liefert [Agent Skills](https://docs.claude.com/en/docs/claude-code/skills) mit — Playbooks, die einem Coding-Agenten (Claude Code, Codex, Cursor) beibringen, wie er eine Blume-typische Aufgabe erledigt, ohne dass du es ihm erklären musst. Sie liegen auf GitHub im Ordner `skills/` des Repos und sind im installierten Paket unter `skills/` gebündelt, sodass jeder Agent direkt auf eine `SKILL.md` verwiesen werden kann.

## Blume

Der zentrale Skill. Er bringt dem Agenten bei, was Blume ist und wie man eine Website aufsetzt, schreibt und konfiguriert — vom Dateisystem abgeleitete Navigation, das Config-Schema, Content-Komponenten — und verweist ihn auf die vollständige Dokumentation, die im installierten Paket gebündelt ist (das Verzeichnis `docs/` innerhalb von `blume`, aufgelöst von dort, wo dein Paketmanager es installiert — in einem pnpm-Monorepo ist das das `node_modules` des abhängigen Workspaces, nicht das Repo-Root). Installiere ihn in jedem Projekt, in dem dir ein Agent beim Erstellen deiner Dokumentation hilft:

```bash
npx skills add haydenbleasel/blume
```

## Migration

`blume-migrate` zieht eine bestehende Dokumentationsseite zu Blume um: Mintlify, Fumadocs, Docusaurus, Starlight, Nextra oder jedes andere Framework. Das Ziel ist idiomatisches Blume statt einer zeilengetreuen Portierung — mit einer Mapping-Referenz für jedes genannte Framework, einer Weiterleitung für jede URL, die sich ändert, und einem Bericht über alles, was dabei wegfällt. Am schnellsten führst du ihn mit [`blume migrate`](/docs/migrating) aus: Der Befehl erkennt dein Framework und öffnet Codex oder Claude Code mit der im Paket gebündelten Kopie. Wenn du ihn mit einem anderen Agenten nutzen willst, installiere ihn:

```bash
npx skills add haydenbleasel/blume --skill blume-migrate
```

## Selbstaktualisierende Dokumentation [#self-updating-docs]

`blume-update-docs` hält deine Dokumentation mit dem Produkt synchron, das sie beschreibt. Bei jedem Durchlauf — typischerweise nach einem Zeitplan, den du in deinem Agent-Runner konfigurierst — prüft der Skill kürzlich gemergte PRs, Changelogs, Config-Schemas und CLI-Hilfetexte gegen die Doku-Inhalte, aktualisiert nur Seiten, die inhaltlich veraltet sind (Arbeiten hinter Feature-Flags werden ignoriert), verifiziert das Ergebnis mit `blume build` und `blume validate` und öffnet oder aktualisiert einen `blume/*`-Pull-Request. Wenn sich nichts verändert hat, meldet er einen sauberen No-Op, statt einen störenden PR zu öffnen.

```bash
npx skills add haydenbleasel/blume --skill blume-update-docs
```

Blume hostet die Automatisierung nicht — binde den Skill in eine geplante Aufgabe in Claude Code, eine Codex- oder Cursor-Automatisierung oder ein schlichtes Cron ein, mit der Berechtigung, die Repo-Historie zu lesen und PRs zu öffnen. Ein typischer wöchentlicher Prompt:

```text
Use the blume-update-docs skill. Review the PRs merged within the last 7 days and compare them to the docs content. Ignore work behind feature flags. If docs need updates, make them, verify the docs build, and open a blume/* PR. If not, report what you checked and do not open a PR.
```

## Den Skill für deine Website schreiben [#writing-your-sites-skill]

`blume-write-skill` schreibt den [Agent Skill für deine eigene Dokumentation](/docs/discoverability/agent-discovery#your-sites-skill): eine einzelne `SKILL.md`, die auf deiner Dokumentation basiert und einem Coding-Agenten beibringt, dein Produkt zu nutzen — Einrichtung, Kernkonzepte, häufige Aufgaben und Stolperfallen —, wobei jedes Thema auf seine Seite verlinkt. Er ersetzt die Seitenübersicht, die Blume unter `/skill.md` generiert. Am schnellsten führst du ihn mit `blume skill` aus: Der Befehl ermittelt, wo der Skill hingehört, und öffnet Codex oder Claude Code mit der im Paket gebündelten Kopie:

```bash
blume skill --claude   # or --codex
```

Wenn du ihn mit einem anderen Agenten nutzen willst, installiere ihn:

```bash
npx skills add haydenbleasel/blume --skill blume-write-skill
```
