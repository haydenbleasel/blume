OpenAPI schema tables and generated examples now keep the JSON Schema constraints they used to drop. A `oneOf` or `anyOf` variant that only lists `required` names now shows those properties as required, where the variant used to read as `any`. The heading says "Exactly one of" for `oneOf` and "At least one of" for `anyOf`, and a schema with both shows both. A map whose `additionalProperties` says what its values are is labeled `map<string, T>`, with its values as a `[key: string]` row, and a free-form `additionalProperties: true` object stays `object`. Enum values render as JSON, so `""` is visible and `null` differs from `"null"`, a `not` reads as `not "reserved"`, and exclusive bounds read as `greater than 0`. A `required` or other keyword beside a `$ref` adds to the referenced schema instead of replacing it, and a property that several `allOf` members constrain keeps every constraint.

Generated request and response examples are now checked against their schema, including `oneOf`, `anyOf`, `not`, `const`, numeric and length bounds, and map values. A sample that fails is retried with each `oneOf` narrowed to each of its variants in turn, then without the `example` and `default` values that break their own schema, keeping the ones that don't. A `oneOf` with a `discriminator`, or whose variants overlap so that no sample matches just one, only needs one matching variant, in the examples and in Try it. If no sample passes, Blume shows no example rather than an invalid one, and request snippets and the Try it prefill send no body. The Try it validator applies the same checks and names the bound a value breaks. A schema that allows only `null` now shows `null` as its example instead of no example. On hand-written API pages, a `placeholder` or `default` that spells a number or boolean is sent as one for a field of that type.
